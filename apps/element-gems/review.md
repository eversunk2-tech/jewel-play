# element-gems Review (Review 담당)

검증일: 2026-11-07 / 대상: `index.html`, `style.css`, `game.js`, `assets/*` (Build 1차 + 에셋·컷인 2차 통합본)

## 1. 요약

**판정: 조건부 통과**

기능·규칙·스킬 6종·컷인·에셋 통합은 직접 확인한 범위에서 모두 정상이고 콘솔 에러/경고 0건, 에셋 404 없음, 누수 징후 없음이다. 소스 수정이 필요한 명백한 결함은 발견하지 못해 **소스 파일은 수정하지 않았다(0건)**.
조건: ① 시간 보너스 때문에 한 판이 60초 타깃을 크게 넘겨 사실상 끝나지 않을 수 있다(밸런스, §5-1), ② 컷인 이미지의 직사각형 크롭 경계가 보인다(에셋, §5-2), ③ `file://` 직접 열기·청각·실기기는 확인하지 못했다(§6). ①은 수치 변경이라 Review 권한 밖이라 제안으로만 남긴다.

## 4. 발견한 문제와 내가 수정한 것

**수정한 소스: 없음 (0건).** 아래는 모두 수정하지 않고 §5에 제안으로 남긴 항목이다. 명백한 결함으로 분류할 만한 코드 버그는 이번 검증에서 재현되지 않았다.

심각도 순 발견 사항(수정 안 함):

3. (낮음) 컷인 중 일시정지 시 컷인 없이 효과만 실행 — §5-3
4. (낮음) BGM 루프 끝 무음 2.3초 — §5-4
5. (낮음) 개발용 `http.server`에서 오디오 일괄 로드 시 일시적 `ERR_CONNECTION_*` — §5-5

## 5. 수정하지 않은 문제와 제안 (밸런스 포함)

### 5-1. 시간 보너스가 과도함 (밸런스, 제안만)
spec은 "60초 + 보너스로 실제 70~90초, 상한 90초"를 의도한다. 그러나 90초는 **남은 시간의 상한**일 뿐이라 보너스(그룹당 +0.5~1.5초, 연쇄 +0.5초)가 소모(수당 약 1.5~2초)를 넘으면 게임이 계속된다.
`game.js`의 순수 함수(`findMatches`, `gaugeGain`, `baseScore`, `timeBonusFor` 등)를 그대로 쓴 노드 시뮬레이션(한 판당 300회, 수당 생각시간 + 스왑·낙하 애니메이션 시간을 게임 시계에 반영, 스킬 효과 근사)으로 본 결과:

| 플레이어 모델 | 게임 지속(중앙값) | 60초 시점 스킬 | 90초 시점 스킬 |
|---|---|---|---|
| 캐주얼(무작위 유효 수, 수당 1.6초) | 약 130초 | 2.6회 | 6.0회 |
| 숙련(12개 중 최대 매치 선택, 1.0초) | 약 456초 | 6.4회 | 10.9회 |
| 빠른 숙련(0.6초) | 3,000초 이상(2,000수에서 중단) | 8.7회 | 14.7회 |

해석: (시뮬레이션은 근사이며 실제 사람의 수치는 다를 수 있음) 캐주얼도 목표(70~90초)를 넘고, 숙련자는 한 판이 수 분 이상 이어질 수 있다. 90초 시점 스킬 횟수는 목표 8~10회에 비해 캐주얼 6회/숙련 11~15회로 편차가 큼.
제안(수치 변경은 Build/기획 판단): ① 보너스를 절반 수준(3매치 +0.25, 연쇄 추가 보너스 삭제 등)으로, ② 또는 총 플레이 시간 상한(예: 120초 소프트 캡 이후 보너스 감소), ③ 또는 보너스 대신 고정 60초. `CONFIG.timeBonus`, `CONFIG.time`만 조정하면 됨.
점수는 캐주얼 약 9~10천, 숙련 수만~수십만(게임이 길어질수록 폭증)이라 최고 점수 비교가 의미 없어질 수 있음. 시간 문제를 해결하면 함께 완화됨.

### 5-2. 컷인 캐릭터 이미지가 직사각형으로 잘려 보임 (에셋, 수정 안 함)
`assets/cutin/{water,grass,lightning,dark,light}.webp`는 이펙트(번개·연기·덩굴)가 이미지 가장자리 알파 255까지 이어져 스크린샷에서 직사각형 경계가 보인다(불은 정상). 에셋 수정 금지라 손대지 않았다. 제안: `.cutin-char img`에 `mask-image`(좌우·상단 페이드, `mask-composite: intersect`)를 적용하거나 이미지를 재생성(가장자리 투명화).

### 5-3. 컷인 중 일시정지/탭 숨김
컷인은 정리되고 재개 후 효과만 즉시 실행(컷인 재재생 없음, 게이지는 이미 소모). 의도된 설계에 부합하나, 탭 숨김이 잦은 모바일에서는 컷인을 못 보는 일이 생길 수 있음. 필요하면 재개 시 컷인을 다시 재생하도록 개선 가능(기능 변경이라 제안만).

### 5-4. BGM 루프 끝 무음 2.3초
`bgm.mp3` 끝 약 2.3초(176.9~179.2초)가 무음이라 루프 때마다 음악이 끊긴다. 에셋 수정 금지. 제안: 트리밍 또는 `timeupdate`로 조기 루프.

### 5-5. 일시적 `ERR_CONNECTION_RESET/REFUSED`
첫 입력에서 효과음 26개 + BGM을 한꺼번에 요청하면 `python3 -m http.server`의 작은 대기열 때문에 일부 연결이 거절될 수 있다. 시험 후 오디오 객체 60개 모두 `error` 없음(브라우저 재시도로 성공), 정식 정적 호스팅에서는 문제 없을 가능성이 높음. 프로젝트 결함이 아니라 개발 서버 한계로 판단.

### 5-6. 기타 제안
- 컷인 길이: 1.3초 × 스킬 8~10회 = 반복 플레이에서 길 수 있음. 건너뛰기가 있어 큰 문제는 아니나 두 번째 판부터는 자동 단축(예: 이미 본 스킬은 0.9초) 고려.
- `index.html`에 `<link rel="icon" href="data:,">`를 넣으면 `/favicon.ico` 404 요청이 사라짐(미수정, 영향 미미).
- BGM 잠금 해제 경합(이론상): `audio.unlock(bgm)`의 `play().then(pause)`가 GO 시점의 `bgmPlay`보다 늦게 끝나면 BGM이 멈출 수 있는 코드 구조임. 모바일 느린 회선에서 가능성이 있으나, `bgm.mp3` 응답을 4초 지연시킨 서버에서 시험했을 때 재현되지 않았다(GO 이후 4초 시점에 정상 재생). 관찰 대상으로만 기록.

### 8-4. 발견한 문제와 수정한 것

**수정한 소스: 없음(0건)**. 명백한 결함은 재현되지 않았다. 아래는 모두 수정하지 않은 항목(심각도순)이다.

1. (낮음·문구) 시작 화면 규칙·난이도 설명이 한글 음절 단위로 줄바꿈된다(390폭에서 "3개 이/상", "버튼/이" 등, 360폭에서는 "3개/이상"). `word-break`가 기본값이기 때문. 제안: `.rules li, .level-desc`에 `word-break: keep-all`(+`overflow-wrap: anywhere`). 기능 문제 아님이라 수정하지 않음.
2. (낮음·문구) 규칙 3줄 "제한 시간은 **N초**!"는 시작 시간이고 실제로는 매치 보너스로 늘어난다(상한 95/90/75). 오해 방지로 "기본 N초(매치하면 늘어나요)" 등으로 다듬는 것을 제안. 난이도 설명·뱃지·종료 문구의 오탈자는 없음.
3. (낮음·에셋) 보석 webp 가장자리 매트 잔여물(§8-3 이미지 표). 에셋 수정 금지라 두고, 필요하면 재생성/알파 정리.
4. (낮음) `loadSave`에서 `bestByLevel`이 있지만 모든 값이 비정상이면 같이 있는 유효한 `best`를 중수로 이관하지 않음(예: `{best:500,bestByLevel:{easy:"x",normal:-5,hard:null}}`→ 중수 0). 정상 경로에서는 발생하지 않는 손상 조합이라 수정하지 않음.
5. (참고) 컷인 중 일시정지 후 재개 시 컷인 없이 효과만 실행되는 설계는 §5-3 그대로.

### 8-5. 수정하지 않은 문제와 밸런스 제안 (지침 항목 7, 제안만)

**방법(독립 시뮬레이션)**: `game.js` 순수 함수를 그대로 쓰고 보드·중력·리필·연쇄·점수·게이지·시간 보너스(경과 90초 이후 ×0.5)·재섞기를 실제 게임 시계로 재현. 가정: ① 수당 생각시간은 균등분포 구간, 잠금(애니메이션) 구간 뒤에 시작 ② 스왑 150ms, 단계별 제거 220ms, 낙하 칸당 80ms(최대 400)+30ms, NO MOVES 시 0.45+0.42초(+칭찬 시 0.5), 불 0.16/풀 0.5/번개 0.06×개수+0.14초 ③ 컷인은 시계 정지라 제외, 스킬 연출·효과는 `game.js` 값 사용 ④ 무작위 유효 수 선택(캐주얼), 게이지 가득 시 60%로 다음 수 대신 발동(발동 지연 1초), 불·풀 조준은 무작위 칸, 번개는 무작위 색, 물/어둠/빛은 효과만 ⑤ 난이도 프리셋은 `applyDifficulty`로 적용, 난이도·모델당 300~600판, 재현 가능한 시드, 종료 안 된 판 0·스킬 0회 판 0.

- 숙련 모델은 ②보다 훨씬 빠르게 스킬을 쓰고 판이 매우 길다(초보 중앙값 234초, 상한 90초 이후 보너스 ×0.5가 있어도). 감쇠 없을 때 345초 → 감쇠 ×0.5에서 234초(고수는 변화 없음, 중수 139→133). **초보에서 숙련자의 판이 4분 가까이 이어지는 문제는 ×0.5로 절반만 해결**된다. 제안(수치 변경이므로 제안만): 두 번째 단계(예: 경과 150초 이후 ×0.25)를 추가하거나 경과 상한(예: 초보 150초)을 두는 것. (참고: 다른 작업이 spec에 §17 플레이 시간 3분 전환을 추가 중이라, 판 길이 정책이 바뀌면 이 제안은 재산정 필요)
- **게이지 조정안(제안만, 현재 값 유지 권장 후 사람 플레이로 판단)**: 사람 플레이에서 ③에 가깝게(스킬이 목표 아래로) 나오면 게이지 최대치를 약 ×0.85로 낮춘다.

| 난이도 | 현재 (불/물/풀/번개/어둠/빛) | 제안(×0.85 반올림) |
|---|---|---|
| 초보 | 10/12/10/11/12/13 | 9/10/9/10/10/11 |
| 중수 | 11/13/11/12/13/15 | 9/11/9/10/11/13 |
| 고수 | 12/14/12/13/14/16 | 10/12/10/11/12/14 |

제안 적용 시 시뮬레이션: ① Plan형 17.6/12.2/7.5회(초보·중수가 목표 상한 초과), ② 중간 14.6/10.3/6.3회(전부 목표 안), ③ Build형 12.2/8.7/5.2회(전부 목표 안). 판 길이는 ①~③ 모두 목표 안(초보 105~119, 중수 82~90, 고수 63~66초). 즉 제안은 ②·③에서 안전하지만 ①이 참이면 과잉이다 → 결정은 사람 플레이 이후로 미루길 권장.

### 8-6. 확인하지 못한 것과 사유

| 항목 | 사유 |
|---|---|
| 사람이 직접 플레이한 재미·실제 스킬 횟수·판 길이 | 자동 시뮬레이션(근사)과 합성 입력만 사용. 스킬 횟수는 위 표처럼 사람의 생각시간에 민감해 확정 불가 |
| "유효한 수가 그 2×2 수 하나뿐인 보드"에서 힌트 시험 | 무작위·변이 탐색으로 그런 8×8 보드를 만들지 못함. 대신 `listMoves`와 "모든 인접 스왑 실적용 후 `findMatches`" 집합이 300보드에서 완전 일치함과 2×2 전용 스왑이 목록에 포함됨을 확인 |
| 페이지 로드 시점부터 `localStorage`가 차단된 실제 환경 | 내장 브라우저에서 차단 모드를 만들 수 없음. 함수 단위 예외 주입(`Storage.prototype`)과 코드(모든 접근 `try/catch`)로 대체 |
