## 설명 문구(§20.14) 작업 규칙
- 초안 문구(불 "누른 칸 둘레 3×3을 한꺼번에 터뜨려요(조준)" 등)를 **`game.js`의 스킬 구현을 직접 읽고 사실과 일치하는지 확인**한 뒤 확정한다(예: 물 "시간 정지"가 정말 시간이 멈추는 것인지, 번개가 몇 개를 맞히는지, 어둠 배율과 지속 시간, 빛이 시간·힌트를 주는지). 어긋나면 문구를 사실에 맞게 고치고 보고한다.
- 난이도마다 달라지는 수치(`CONFIG.difficulty[*].skills`)는 문장에 쓰지 않거나, 쓴다면 현재 난이도 값에서 읽어 온다.
- 초등학생이 읽을 쉬운 말, 한 줄 20자 안팎·최대 2줄, 설명은 `CONFIG` 한 곳에 모은다.

## 휴대폰 회귀 방지 (최우선)
- 휴대폰 세로(360×640, 390×844)와 기존 가로(844×390, 800×360)는 **전후가 동일**해야 한다. 작업 **시작 전에 현재 상태의 시험용 사본을 scratchpad에 만들어** 기준으로 삼고, 시작·게임·레벨 선택·명예의 전당·프로필·결과·일시정지·팝업·컷인 장면을 **전후 스크린샷 픽셀 비교**한다(Plan의 `compare.js` 참고). 갱신 시각 글자·아바타 디코딩 같은 잡음은 구분해 보고한다.
- `game.js` diff는 설명 요소·`CONFIG` 문구 추가 외에 없어야 한다(`git diff -- game.js`로 직접 확인).
- 래퍼 `div` 추가가 `ranking-ui.js`의 화면 선택자(`#screen-*` 등)·포커스 이동·`inert` 처리를 깨지 않는지 확인.

## 시험 (필수)
- Node: `node --test test/*.test.js`(앱 폴더 기준) 통과 + `game.js`가 `module.exports` 가드로 불러지고 `CONFIG.skillInfo`가 6원소 모두 있는지 등 새 시험. `node --test server/test`는 건드리지 않았으므로 통과 상태 유지 확인.
- 브라우저: **새 탭 + `tabId` 명시 + 로컬 서버(`localhost`)만**, `localStorage` 접근 전 `location.origin` 확인, **배포 주소(`github.io`)·기존 탭·실제 Cloudflare 서버(`workers.dev`)는 열거나 요청하지 않는다**. 서버 주소가 필요하면 목 서버(`node server/mock/server.js --port <포트>`)를 쓰고 시험 후 종료한다. 프로젝트 파일에 로컬 주소를 남기지 않는다.
- 와이드 뷰포트: 1366×768, 1280×720, 1280×800, 1920×1080, 1024×768, 900×501(경계), 799/800 폭 경계, 820×1180·768×1024(세로 태블릿), 1366×657(주소창 있는 크롬북). 각 해상도에서 §20.11 체크리스트와 §20.14 수용 기준 ①~⑥, 가로 스크롤 0, 터치 타깃 ≥44px, 콘솔 오류 0. 입력(마우스 클릭·드래그, 터치 에뮬레이션), **스킬 6종 발동**(가득 참 → 누르기 → 조준 → 컷인 → 효과), 일시정지·결과, 게임 중 창 크기 변경에도 좌표가 맞는지.
- 실제 스테이지 클리어까지 한 판(시험용 조작이 필요하면 scratchpad 사본에서만).
- 마무리 후 뷰포트 에뮬레이션을 `desktop` 프리셋으로 되돌리고 탭·서버·헤드리스 프로세스를 정리한다.
