## ⚠ 브라우저 사용 주의
- 과거에 `tabId` 없이 `javascript_tool`을 실행해 **배포 사이트(eversunk2-tech.github.io) 탭의 localStorage를 덮어쓴** 사고가 있었다. **모든 브라우저 호출에 `tabId`를 명시**하고, **새 탭**을 만들어 **로컬 서버 탭(`http://localhost:<포트>/`)에서만** 시험한다. `localStorage` 읽기/쓰기 전에 `location.origin`이 로컬인지 확인한다. 배포 주소와 기존에 열려 있는 탭은 건드리지 않는다. 로컬 서버는 **프로젝트 폴더 자체**를 루트로 띄운다(scratchpad의 옛 복사본은 에셋이 오래돼 쓰지 않는다). 시험을 위해 `state`를 조작하거나 목표를 낮출 때만 scratchpad에 **최신 프로젝트의 새 복사본**을 만들어 쓴다. 점검 후 서버·탭을 모두 정리한다.

## 승인된 결정 (§18.8 열린 질문의 답)
1. **컨셉 ① 스카이 캔디**, 보드는 **어두운 트레이 유지**(밝은 보드 금지: 흰 보석 대비 1.2:1).
2. **폰트는 시스템 폰트만**(woff2 파일·CDN 추가 없음). 굵기·글자 외곽선(stroke)+그림자 레시피(§18.3.3)로 게임풍 표현.
3. **새 로고**: 메인 세션이 Gemini로 만들어 **`assets/title-logo.webp`를 같은 경로·같은 파일명으로 교체**한다(종횡비 약 972×569, 투명 배경, 아래쪽 글자 2줄 + 위쪽 보석 호). **마크업의 로고 경로는 바꾸지 않는다.** 새 로고 도착 전에는 현재 로고로 시험하고, 로고 영역(너비·여백)은 종횡비가 비슷한 이미지가 들어와도 레이아웃이 깨지지 않게 `max-width`/`aspect-ratio` 기준으로 잡는다.
4. **새 배경 이미지(`bg-sky.webp`)는 만들지 않는다.** 하늘·구름·언덕·반짝임은 **CSS만으로** 구현(§18.5 "CSS만으로 해결"). 이 결과 `bg-jungle.webp`를 더 이상 참조하지 않도록 정리한다(파일 자체 삭제는 메인 세션이 한다).
5. **컷인 캐릭터는 그대로**(재생성 없음). 단, 컷인·말풍선·스킬 이펙트가 새 밝은 하늘 배경·어두운 트레이 위에서 눈에 띄는지 확인한다.
6. **장식 모션은 최소**(구름 느린 이동, CTA 약한 바운스 정도). `prefers-reduced-motion`에서는 정지/축소.

## 구현 순서 (§18.6 6단계를 따른다. 단계마다 브라우저로 확인하고 다음 단계로)
1. 토큰·배경(하늘 그라디언트+구름+언덕+반짝임)·카드/패널·버튼(공통) → **시작 화면** 완성. WCAG 대비 측정(§18.3.2 표)을 직접 한다.
2. **보드**: 타일 SVG data-URI 배경(`.board` 배경 반복, 64칸 DOM 추가 금지) + 프레임 + `.gem`의 칸 상태(`::before`, 이미지 뒤에 그려짐). **칸마다 `drop-shadow`/`filter`/`backdrop-filter`를 쓰지 않는다**(§18 성능 방침, 선택/물 보석 밝기 보정만 예외). 6종 식별·상태 5종(기본/선택/힌트/커서/제거) 확인.
3. HUD(타이머 바·점수·목표 진행 바·난이도 칩)·게이지 버튼 6개·하단 버튼, **가로 모드** 보정.
4. **레벨 선택** 화면, 오버레이(일시정지/확인/결과), 칭찬 팝업, 카운트다운, 컷인 말풍선과의 톤 정합.
5. 모션(CTA·구름·칸 힌트)과 `prefers-reduced-motion`, `file://` 직접 열기 확인(가능한 범위).
6. 최종 회귀 점검. 죽은 규칙 정리는 하지 않는다(덧붙여 덮어쓰기 방침).
- 방침: 기존 규칙 삭제를 최소화하고 `style.css` 끝에 "5차 Build: 리디자인" 블록을 덧붙여 덮어쓴다(§18.6).

## 유지 조건 (회귀 금지)
- 보석 6종의 **모양 구분**(색약 대응) 유지, 터치 타깃 ≥ 44px, 360×640 ~ 1280×800 및 가로 모드에서 **가로 스크롤 없음**, `--ui-h` 계산·보드 크기 불변(시작 [시작] 버튼 54→60px 변경만 허용).
- 게임 로직·수치·저장·사운드·컷인 흐름·스테이지 규칙은 변경 금지. 3·4차 Review에서 수정된 가로 모드 보정(`.goal`, 결과 버튼 한 줄)을 깨지 않는다.

## 자체 점검 (완료 전 필수)
- Node 단위 테스트 재통과(기존 순수 로직: 매치·2×2·힌트·스테이지·저장; `game.js`를 건드리지 않았으면 해시 동일 확인으로 갈음 가능).
- 브라우저(프로젝트 폴더 서버, `tabId` 명시): 시작 → 난이도 선택 → 레벨 선택 → 게임 → 스킬 컷인 → 일시정지/결과(클리어·실패)까지 한 바퀴, 콘솔 에러 0건.
- 390×844, 360×640, 768×1024, 1280×800, 가로 844×390 스크린샷으로 가로 스크롤·잘림 점검, **6종 보석 식별(흑백 변환 포함)**, 칸 상태 표현, 흰 보석 대비, 레벨 카드 글씨 가독성(현재 약 10px — 가능하면 11px 이상).
- spec §18.7 체크리스트를 스스로 훑어 명백한 누락이 없게 한다(정식 검증은 Review).
