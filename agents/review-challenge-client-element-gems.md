## 확인할 것 (각각 근거)
1. **범위**: `git status --short`·`git diff --stat HEAD`로 바뀐 파일이 소유권 안인지(일반용 클라이언트·공용 파일·교육용 이식·교육용 `edu.css`·`tools/SYNC.md`·두 앱 `index.html` 프로필 문구 한 곳; 서버는 B-S의 것). 설계·수치(120초·`scoreCap` 280000·`submitDelaySec` 300·점수 규칙 §28·미션 표 §43·별 기준 §44)가 안 바뀌었는지(`CONFIG` HEAD 대비 `challenge` 외 동일).
2. **도전 판 규칙(핵심)**: 실제 `game.js`로 확인 — 시간이 **120초에서 끝나고** 시간 보너스·빛 스킬 시간 +초가 0, 물 정지·컷인은 원래대로, 목표·미션·별·스테이지 기록(`stages`·`progress`·`bestByLevel`·`plays`)을 건드리지 않음, `goalMet()` 항상 거짓, **같은 시드·같은 행동으로 스테이지 규칙과 도전 규칙을 돌렸을 때 점수가 같음**(시간 보너스 제외), 점수가 §28 그대로. 도전 후 스테이지 모드로 복귀가 정상. 일시정지·다시 시작·나가기·돌아가기·명예의 전당 보기 흐름.
3. **점수 분포 재측정**: Plan 하네스(`…/scratchpad/plan-challenge/score-cap/`의 `chsim.js`·`run-cap.js` 등을 **새 폴더에 복사**해 쓴다. 단 `SNAP`을 **작업 트리의 현재 일반용 `game.js` 사본**으로 바꿔 B-C가 만든 `CONFIG.challenge` 규칙을 그대로 실행)로 새 시드 **93,000,000~**에서 N0(중수 값·균등 보드·120초 고정)를 B·A·X1·X3·XS 칸당 **300판 이상** 돌려 Plan 표 1(평균 B 32,300·A 38,411·X1 47,281·X3 61,649·XS 103,432)과 평균이 **±5% 안**인지, `scoreCap` 280000·점검선 120,000이 새 최댓값을 넘지 않는지. 도전 판이 하네스 가정(`targets` 1e9·시간 보너스 0)이 아니라 **B-C의 실제 `startChallenge` 경로**로 돌 때도 같은 분포인지(가능하면 `startChallenge`를 직접 호출하는 하네스로 B·X1 각 100판 비교). 시간 보너스·빛 시간이 실제로 0인지.
4. **저장·마이그레이션**: 옛 일반용·교육용 저장(`challenge` 없음)이 깨지지 않고 열리는지, 손상 값·규칙 표식 불일치 처리, `eraseDevice`/"프로필 지우기"가 `challenge`도 지우는지, 로컬 `localStorage` 키가 바뀌지 않았는지.
