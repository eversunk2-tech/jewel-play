## 확인할 것
1. **범위**: `git show --stat HEAD`가 위 파일뿐인지, `git diff HEAD~1 -- apps/element-gems-edu/game.js apps/element-gems-edu/edu.js`가 **3곳(기본값·주석·안전 기본값)뿐**인지 줄 단위로 직접 읽는다. 표(`missions`)·`wild`·`many`·`learn`·`easyTargets`·점수·도전 모드·정령·일반용·서버·`edu-data`·`style.css`·`ranking*.js` 무변경.
2. **다른 곳에 'many' 기본이 남았는지**: `grep -rn "'many'" apps/element-gems-edu/game.js apps/element-gems-edu/edu.js`로 모든 'many' 사용처를 훑어, 기본값 역할을 하는 곳이 더 없는지(예: `defaultSave`, `parseSave`/`cleanEduField`, `edu.js` 초기화·`resetEdu`·프로필 지우기 뒤 복구, 라디오 초기 선택, 시작 화면 한 줄 문구, 단원 선택 게이트의 문구, 레벨 카드/설명판의 모드 분기, `index.html` 정적 `aria-checked`/`class` 초기 상태). 정적 마크업이 "많이"를 미리 선택 상태로 두고 있으면 JS가 덮어쓰기 전 깜빡임이 생길 수 있으니 `index.html`·`edu.css`도 확인한다.
3. **실제 화면(핵심, 헤드리스 Chrome, 로컬 사본만)**: (a) **저장 없는 새 브라우저**(빈 `localStorage`)로 교육용 앱을 열어 선물상자 문제 양 라디오가 **"보통" 선택**, 시작 화면 한 줄 "선물상자 문제: 보통"(단원을 고른 뒤 보이는 곳 포함), 레벨 카드의 중수·고수 미션 숫자가 **"보통"(= 일반용 §43 표)** 값(중수 1단계 "불 보석 25개", 고수 1단계 "한 번에 4개 이상 15번")인지. (b) "많이"를 직접 누르면 즉시 저장되고 카드 숫자가 "많이" 값(30개/18번)으로 바뀌며 **새로고침해도 "많이" 유지**되는지, 다시 "보통"을 누르면 돌아오는지. (c) `localStorage`에 `edu.intensity: 'many'`가 저장된 기기는 그대로 "많이", `edu` 저장은 있는데 `intensity`가 없는 옛 저장은 "보통"인지. (d) 판을 한 번 시작해 HUD가 "보통" 모드(예: 학습 칩 0/0, 보통 중수 1단계 0 / 25)인지, 선물상자(?)가 "보통" 공급으로 나오고 문제 팝업이 정상인지(단원 하나 고른 상태에서 몇 수), 콘솔 오류 0. (e) 1280×720·390×844 두 크기에서 라디오 모양·선택 표시·넘침 없음(스크린샷으로 확인). 일반용 앱에는 이 라디오가 없고 변화가 없는지 한 번 열어 본다.
4. **시험 약화 점검(핵심)**: `git diff HEAD~1 -- apps/element-gems-edu/test`를 전수로 읽는다. 지워지거나 느슨해진 단언이 없는지(기대값 'many'→'normal' 변경과 이름·메시지 갱신, 추가한 단언·새 시험뿐이어야 한다). 바뀐 기대값이 새 설계에서 맞는지, "기본값을 바꾸면 따라간다" 같은 시험이 기본값이 'normal'이 된 뒤에도 **여전히 의미가 있도록** 'many'로 덮는 줄이 함께 들어갔는지(트리비얼해진 단언이 없는지). 새 시험(`⑥ 실제 기본 선택(spec §47)`)이 실제 `G.CONFIG.edu.defaultIntensity`를 쓰는지.
5. **변이 시험(scratchpad `git clone --local` 복제본에서)**: ① `CONFIG.edu.defaultIntensity`를 다시 'many'로 ② `EDU_UI.intensity.default`를 다시 'many'로 ③ `eduIntensity()`의 마지막 줄을 옛 모양으로 ④ `normalizeEdu`의 저장값 우선순위를 뒤집기(저장된 값을 무시하고 기본값 반환) ⑤ 새 기기의 기본이 'normal'이어도 저장된 'many'를 'normal'로 덮어쓰는 경로 만들기(예: `readEduFromRaw`가 항상 기본값) — 각각 교육용 시험이 실패하는지(어느 시험이 잡는지 적는다). 잡히지 않는 변이가 있으면 보고한다(시험 구멍; 명백하면 시험 한 줄 보강).
6. **영향 범위 문장의 사실성(spec 47.2)**: "이미 값이 저장된 기기는 그대로 / intensity 없는 옛 저장·저장 없는 새 기기만 보통"이 코드 경로와 맞는지(저장이 언제 쓰이는지: `edu` 객체가 단원 선택·문제 양 선택·통계 갱신 때 저장되는지, 첫 실행만으로 `intensity: 'many'`가 저장되던 경로가 있었는지 — 있었다면 이미 접속한 기기가 '많이'로 굳어 있다는 문장이 맞는지). 틀린 문장이 있으면 보고(§47은 고치지 말고 제안으로).
7. **시험 실행**: `node --test apps/element-gems-edu/test/*.test.js`(기대 599 중 598 통과+건너뜀 1), `node --test apps/element-gems/test/*.test.js`(기대 342), `node --test apps/element-gems/server/test/*.test.js`(기대 126), `node apps/element-gems-edu/tools/validate-edu-data.js`(오류 0·경고 0).
