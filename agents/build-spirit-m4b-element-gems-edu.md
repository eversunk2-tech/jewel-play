# Build 지침 M4-B — 교육용: 정령 특별 레벨 이식 + "정령에게 선물 드리기" (spec §27.6·§27.7·§27.8·§27.9 M4)

## 역할
너는 **Build 담당**(Sonnet 서브에이전트)이다. 앞 단계 **M4-A가 일반용에 만든 정령 특별 레벨 프레임**을 교육용 `apps/element-gems-edu/`에 **같게 이식**하고, 교육용에만 있는 **학습 칩 이름 변경**을 더한다. 일반용 `apps/element-gems/**`는 **읽기 전용 기준본**이다(M4-A 결과가 이미 작업 트리에 들어 있다 — 시작할 때 `git status`·`git diff --stat`·`git diff -- apps/element-gems`로 변경분을 확인하고 `agents/build-spirit-m4a-element-gems.md`를 읽는다). **게임 규칙·목표 값·점수·학습 조건 N·문제 공급·저장 구조는 바꾸지 않는다.** 검증은 별도 Review가 하며, **네가 직접 확인한 것만 "확인함"** 으로 쓴다.
프로젝트 규칙은 `CLAUDE.md`, 진행 상황은 `docs/STATUS.md` §14, 이식 절차는 `apps/element-gems-edu/tools/SYNC.md`(끝의 M3 기록 포함)를 먼저 읽는다. 정답지는 `apps/element-gems/spec.md` **§27.6·§27.7·§27.8·§33·§38~§39**와 M4-A 지침의 "승인된 결정" 전부(그대로 적용: F1 프레임, 새 에셋·효과음 없음, 비폭력 문구 가이드, 초보는 점수제 표현만, 새 저장 필드 없음).

## 이식 규칙
- **일반용의 M4-A 변경(`game.js`·`index.html`·`style.css`의 정령 관련 부분)을 교육용에 같게 반영**한다. 교육용 `style.css`는 일반용과 **바이트 동일**이어야 한다(`cmp`로 확인, 기존 시험 `edu-ui.test.js`·`edu-profile-share.test.js`가 검사). 교육용 `game.js`·`index.html`은 일반용 복사본이므로 **`// [EDU]` 표식이 붙은 기존 차이를 해치지 말고** 정령 코드를 같은 모양으로 더한다(순수 함수 `spiritOf`·`spiritStep`은 두 앱 소스가 글자 그대로 같아야 한다 — 기존 "순수 함수 소스 동일" 시험 목록에 추가하고 이유를 주석에 적는다).
- 교육용에만 있는 요소를 정령 패널과 **함께** 잘 배치한다: 교육용 판에는 점수/미션 칩 말고도 **학습 칩(`#learn-chip`)**이 있다. 특별 레벨 = (정령 패널, 중수·고수는 SEQ 칩 포함, ≤ 93px) + (학습 칩, 많이 모드일 때만). 이 합이 **이미 있는 "미션 칩 2개 + 학습 칩" 상황보다 높지 않아야** 한다(M3-B가 측정·허용한 한도) — 해상도별로 재서 보고.

## 교육용만의 변경 `[EDU]`
1. **특별 레벨의 학습 칩 이름**: 학습 조건이 있는 특별 레벨(5·10단계, 많이 모드)에서 칩 이름을 "선물상자 문제 풀기" 대신 **"정령에게 선물 드리기"**로 한다. 작은 글 "맞든 틀리든 푼 개수예요"·진행 `3 / 9`·완료 ✓·`role="progressbar"`·aria(`aria-label`은 "정령에게 선물 드리기 3 / 9, 완료")·완료 낭독("정령에게 선물 드리기를 끝냈어요")도 같은 이름으로. **특별이 아닌 레벨의 칩 이름과 문구는 그대로**("선물상자 문제 풀기"). 문제 팝업 제목("선물상자 문제")·`end-quiz` 줄은 그대로.
2. **레벨 선택 설명판의 학습 줄**(`#sd-learn`): 특별 레벨만 "정령에게 선물상자 문제 N개를 드려요"(쉬운 말, 같은 N). 다른 레벨은 기존 "선물상자 문제 N개도 풀어요".
3. **목표(퍼즐 미션/점수)를 먼저 채웠는데 학습 조건이 모자란 때**(특별 레벨): 정령 단계 k는 n이 되어 그림은 컬러지만 판은 이어진다. 이때 제목을 "{이름} 정령이 거의 깨어났어요", 낭독/알림을 "거의 다 깨어났어요! 선물상자 문제를 마저 풀어 줘요"로 하고, **"깨어났어요! 고마워요" + 마지막 빛 번짐 + 효과음은 판이 실제로 끝났을 때(`stageDone()`)만** 낸다. 일반용은 목표를 채우면 곧 판이 끝나므로 이 상태가 없다 — 이 분기는 `[EDU]` 블록으로 둔다. 실패(시간 초과)로 끝나면 결과 줄은 "아직 잠이 덜 깼어요. 다시 도전해요! (깨어남 k/n)"이고, 학습이 모자랐다면 기존 `end-target`의 "· 선물상자 문제 n/N" 줄은 그대로 유지한다.
4. **보통 모드·문제 못 불러온 경우**(학습 조건 없음): 학습 칩 없음, 정령 패널은 일반용과 같다.
5. 교육용 목표 점수는 일반용 × 1.2(초보)·모드 표라서 **초보 정령 단계의 점수 경계가 교육용 목표에서 계산**되는지 확인한다(`state.target`을 쓴다 — 일반용 숫자를 하드코딩하지 않는다).
6. 교육용 `index.html`의 규칙/도움말에 정령 안내가 일반용에 들어갔다면 같은 문구를 이식한다(M4-A 보고 참고).

## 시험
- 일반용 신규 `test/spirit.test.js`의 교육용 대응 시험(교육용 `test/spirit.test.js` 신규): 표·`spiritOf`·`spiritStep`(교육용 목표 기준 경계값)·DOM·결과 줄·깨운 정령 수·문구 점검·CSS(reduced-motion)·새 에셋 0 — 그리고 교육용만: ① 특별 레벨 + 많이 모드에서 학습 칩 이름이 "정령에게 선물 드리기", 특별이 아닌 레벨은 "선물상자 문제 풀기" ② 보통 모드/문제 못 불러옴이면 학습 칩 없음 ③ 목표를 채웠지만 학습 모자람 → "거의 깨어났어요" 상태에서 판이 이어지고, 학습을 채우는 순간 `stageDone()`·"깨어났어요! 고마워요"·효과음 한 번 ④ 시간 초과 실패의 결과 줄 ⑤ 판 도중 문제 양이 바뀌어도 그 판의 정령/학습 값이 유지됨(기존 불변식).
