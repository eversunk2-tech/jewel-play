## 검증 항목
1. **spec §20.11 체크리스트 전체**를 표(항목 / 결과 / 근거)로.
2. **휴대폰 회귀(최우선)**: 360×640, 390×844, 가로 844×390, 800×360에서 **현재(`31f6530`)와 직전(`git show 4d0ddb3:…` 또는 `31f6530^`)의 사본**을 같은 조건(난수 고정·애니메이션 정지·흐르는 값 숨김)으로 비교한다. 시작·게임·레벨 선택·명예의 전당·프로필·결과·일시정지·팝업·컷인 장면. 차이는 위치·크기·픽셀 단위로 분류(잡음 vs 실제 차이). `style.css` diff가 **삭제 0줄·끝 블록 추가뿐**인지, `game.js` diff가 설명·`skillDesc`·마크업·`aria-label` 범위뿐인지 직접 확인.
3. **분기 조건 경계**: 799/800, 500/501 높이·폭, 559/560, 699/700, 899/900, 959/960. 와이드↔휴대폰 가로 규칙이 겹치거나 빠지는 해상도 없음. 창 크기를 게임 중에 바꿔도 좌표가 맞는지(드래그·클릭).
4. **와이드 측정**: 1366×768, 1280×720, 1920×1080, 1024×768, 1180×820, 1366×657, 900×501에서 보드 크기(spec 표와 비교), 가로·세로 스크롤 0, 패널이 보드 밖으로 넘치지 않음, 터치 타깃 ≥44px, 콘솔 오류 0.
5. **§20.14 게이지·설명**: 6행 × 1열이 모든 와이드 해상도에서 보이는지, 설명이 잘리지 않고(말줄임 없음) 낮은 화면(설명 숨김 구간)에서 이름만 보이는지, 막대 채움·가득 참·조준·잠금 표현, 글자 대비(막대 위·잠금 상태 `opacity .7` 포함) **수치 측정**, `prefers-reduced-motion`(CDP 에뮬레이션), 컨테이너 쿼리 미지원 폴백 동작.
6. **설명 문구 ↔ 실제 스킬 일치**: `game.js`의 스킬 6종 구현을 직접 읽고 문구가 사실인지 판정(불 3×3, 물 시간 정지, 풀 가로·세로 한 줄, 번개 같은 색 보석 최대 N개, 어둠 ×2, 빛 +시간·힌트). 난이도(초보·중수·고수)를 바꿔도 문구가 거짓이 되지 않는지, 초등학생이 읽을 쉬운 말인지.
7. **게임 기능 회귀(실제 플레이)**: 와이드에서 스킬 **6종 모두 발동**(가득 참 → 누르기 → 조준(불·풀) → 컷인 → 효과), 마우스·터치 에뮬레이션, 일시정지·계속·리셋 확인, 실제 스테이지 클리어와 TIME UP(실패) 결과 화면, 컷인 건너뛰기, 연쇄·2×2 매치. 점수를 조작하는 시험은 scratchpad 사본에서만.
8. **기타 화면**: 시작·프로필(닉네임 오류·지우기 확인)·명예의 전당(내 순위 바, 503·오프라인 안내)·레벨 선택(5×2)·팝업·결과·일시정지의 와이드 배치, **프로필 안내 팝업(§19/프로필 흐름)과 `ranking-ui.js`의 화면 전환·포커스·`inert`가 래퍼 div 추가 후에도 정상**인지(키보드만으로 전체 흐름).
9. **세로 태블릿**: 768×1024(676), 820×1180(680), 1080×1920(840), 접이식 673×841.
10. **접근성**: Tab 순서·`:focus-visible`, 게이지 버튼 `aria-label`(설명 포함 문장의 자연스러움), 줌 200%, 대비 WCAG AA 표(색 실측).
11. **성능**: 큰 보드에서 `backdrop-filter`·칸당 `filter` 개수, 애니메이션 속성(`transform`/`opacity`) 정적 점검. 가능하면 CPU 4× 스로틀 프레임 측정(못 하면 못했다고 명시).
12. **자동 시험·위생**: `node --test test/*.test.js`(60), `node --test server/test`(65), `node server/build.js --check`, `git status`로 예상 밖 변경·시험 흔적·로컬 주소 없음(`git grep`).
