# 추가 지침 — 별 챔피언 "전체 점수"를 난이도 가중(1·2·3)으로 변경

> 사용자 승인(2026-11-07): spec §19.12 질문 1의 **단순 합(대체됨)** → **난이도 가중 합 "별 점수"**. 이 문서는 `build-ranking-server-element-gems.md`(A), `build-ranking-client-element-gems.md`(B)의 **해당 부분을 대체**한다. 나머지 지침과 파일 소유권은 그대로다. 커밋·푸시·wrangler 금지, 브라우저 안전 규칙도 그대로.

## 새 규칙 (정답)
- **별 점수(전체 탭의 점수)** = 초보 별 ×**1** + 중수 별 ×**2** + 고수 별 ×**3**. 최대 30 + 60 + 90 = **180**.
- **난이도 탭**(초보/중수/고수)은 지금처럼 **별 개수**(0~30)로 정렬·표시한다. 가중은 전체 탭에만 적용.
- 정렬은 그대로: 점수(전체 탭은 별 점수) → **남은 시간 합계(세 난이도 단순 합, 가중 없음)** → 먼저 달성 → id.
- 가중치는 코드 한 곳(상수 `STAR_WEIGHT = { easy: 1, normal: 2, hard: 3 }`)에만 둔다. 서버와 클라이언트 표시용이 일치해야 한다.
- 응답/저장: DB 컬럼 `total_stars`는 이름을 유지하되 **가중 점수**를 저장한다(주석으로 명시, 스키마 주석 갱신). `me.stars.all`·leaderboard `board:"all"`의 `stars`·rank 응답의 `stars`는 가중 점수다. 난이도별 `stars.easy/normal/hard`는 별 개수 그대로다.
- 서버 상수 `max total`은 180. 이상치 점검 SQL 예시(`total_stars = 90`)는 180 기준으로 바꾼다.

## A (서버·닉네임) 할 일 — 소유: `apps/element-gems/server/**`
1. `src/core.js`에 `STAR_WEIGHT`와 `weightedScore(starsByDiff)`를 추가하고, `computeTotals`(또는 해당 함수)의 `totalStars`를 가중 점수로 바꾼다. `total_left`는 단순 합 유지.
2. `up_all`(점수가 오른 시각 갱신)은 가중 점수 기준으로 비교한다.
3. 시험 갱신: 가중 계산(예: 초보 3★, 중수 2★, 고수 1★ → 3+4+3=10), 전체 탭 정렬이 가중 점수 기준(고수 위주 플레이어가 초보 위주 플레이어보다 같은 별 수에서 위), 난이도 탭은 별 개수, 동점 4종 시나리오 재확인, 최대 180, `/api/rank`(all)와 목록 일치(SQL COUNT vs JS 정렬). 기존 61개 시험이 깨지면 새 규칙에 맞게 고친다(규칙을 시험에 맞추지 말 것).
4. `schema.sql` 주석, `README.md`(API 요약·이상치 SQL), `dist/worker.js` 재생성(`node server/build.js`) 후 `--check`와 `node --test server/test` 통과.
5. 완료 보고에 **바뀐 파일과 시험 개수**만 짧게.

## B (클라이언트) 할 일 — 소유: `index.html`, `style.css`(끝 블록), `game.js`(훅·저장만), `ranking.js`, `ranking-ui.js`, `test/`
1. 순위표 **전체 탭** 숫자 라벨을 "★ N개" 대신 **"별 점수 N"**(또는 ★ 아이콘 + 숫자 + 작은 글씨 "점")로 표시하고, 난이도 탭은 기존처럼 별 개수. 내 순위 줄·내 프로필 칩의 전체 값도 같은 규칙. 숫자가 최대 180(3자리)까지 들어가도 360px 폭에서 줄바꿈·잘림이 없게 한다.
2. 순위표 안내 줄/도움말에 **한 줄** 추가: "고수 별은 3점, 중수 별은 2점, 초보 별은 1점이에요." (초등학생이 읽을 쉬운 말.) 시작 화면의 [명예의 전당] 근처에는 넣지 않아도 된다.
3. 클라이언트가 서버 응답을 그대로 표시하는 구조라면 계산 로직은 만들지 않는다. 오프라인 캐시/내 값 계산에 `stars.all`을 합산하고 있다면 **서버 값을 우선**하고, 로컬 추정이 필요하면 `STAR_WEIGHT`를 `ranking.js` 상단 상수로 둔다(서버와 같은 값).
4. 시험 갱신: 라벨 포맷 함수(전체=점수, 난이도=개수), 최대값 180 렌더. 목 서버(A가 갱신 후)로 한 바퀴.
5. 완료 보고의 "spec·지침과 달라진 점"에 이 변경 반영 여부를 적는다.

## 순서
A가 서버를 먼저 고친다(작아서 금방 끝남). B는 A 갱신 전에도 표시 규칙을 구현해 두고, 갱신 뒤 실제 목 서버로 확인한다. 서로의 소유 파일은 수정하지 않는다.
