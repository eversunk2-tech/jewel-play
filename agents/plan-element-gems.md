# Plan 서브에이전트 지침 — element-gems (원소 스킬 보석 퍼즐)

## 역할
너는 **Plan 담당**이다. 구현하지 않는다. 계획서 `spec.md` 한 파일만 작성한다.

## 수정 가능 범위 (엄수)
- 생성/수정해도 되는 파일: `/Users/sungchul/Desktop/워크숍/apps/element-gems/spec.md` **단 하나**
- 그 외 모든 파일·폴더는 읽기만 하고 수정하지 않는다. 코드(html/css/js)는 작성하지 않는다.
- 참고용으로 읽을 파일: `/Users/sungchul/Desktop/워크숍/CLAUDE.md`

## 프로젝트 제약 (CLAUDE.md 요약)
- HTML + CSS + JavaScript만 사용. 백엔드·DB 없음 (저장은 localStorage).
- 외부 라이브러리 최소화 (CDN 허용, 하지만 가능하면 순수 JS).
- 앱은 `/apps/element-gems/` 안에서 자체 완결. 블로그의 다른 파일을 건드리지 않는다.
- 모바일(터치, 세로 화면)에서도 플레이 가능해야 한다.

## 게임 컨셉 (사용자가 선택한 아이디어)
**"원소 스킬 퍼즐"** — Bejeweled Blitz의 Lightning 모드(타이머 바, 점수, 배율, 캐스케이드 카운터, 힌트 버튼, "AWESOME!" 칭찬 팝업)를 참고한 매치-3 보석 퍼즐.
- 보석 색마다 원소 속성이 있고, 해당 색을 매치하면 그 원소의 **스킬 게이지**가 찬다.
- 게이지가 가득 차면 버튼(또는 탭)으로 **스킬을 발동**한다.
- 어떤 색을 먼저 모아 어떤 스킬을 쓸지 고르는 전략성이 핵심 재미다.
- 기본 모드는 **타임어택(약 60초)** 이며, 매치·연쇄 시 시간이 소폭 늘어난다. (Lightning 방식)

### 원소 스킬 초안 (더 좋은 안이 있으면 근거와 함께 수정해도 됨)
| 색 | 원소 | 스킬 |
|---|---|---|
| 빨강 | 불 | 선택한 칸 중심 3×3 폭발 |
| 파랑 | 물 | 시간 정지 5초 (타이머 멈춤) |
| 초록 | 풀 | 한 행 + 한 열 제거 (십자) |
| 노랑 | 번개 | 무작위 같은 색 보석 여러 개 연쇄 제거 |
| 보라 | 어둠/마법 | 점수 배율 ×2 일정 시간 |
| 흰색 | 빛 | 힌트 + 보드 재배치(셔플) 또는 시간 +N초 |

## spec.md에 반드시 포함할 항목
1. **개요** — 한 줄 소개, 타깃 플레이 시간(1회 약 1분), 핵심 재미 포인트
2. **게임 규칙** — 보드 크기(권장 8×8), 보석 종류 수, 스왑 규칙, 매치 판정, 중력/리필, 연쇄(캐스케이드), 유효한 수가 없을 때 처리
3. **원소 스킬 시스템** — 게이지 충전량 공식, 최대치, 발동 방식(PC 클릭/모바일 탭), 각 스킬 동작·연출, 스킬 중 연쇄 처리, 밸런스 의도
4. **점수·시간·배율** — 매치 점수, 연쇄 배율(x1~x5), 시간 보너스 규칙, 칭찬 팝업 조건(GOOD/GREAT/AWESOME 등)
5. **특수 보석(선택)** — 4매치/5매치 보상을 넣을지 여부와 범위. 범위가 커지면 "2차 확장"으로 분리
6. **UI/레이아웃** — 화면 구성(상단 타이머 바, 점수/배율, 보드, 원소 게이지 6개, 힌트/메뉴/리셋 버튼), 시작·종료 화면, 반응형(세로 모바일 우선) 기준
7. **입력 처리** — 마우스 클릭-클릭, 드래그 스왑, 터치 스와이프(Pointer Events 권장)
8. **렌더링/기술 방식** — DOM+CSS vs Canvas 중 하나를 **근거와 함께 선택**. 보석은 색약 사용자를 위해 색뿐 아니라 **모양도 다르게** 한다. 애니메이션 방식, 효과음(WebAudio 사용 여부)
9. **저장 데이터** — localStorage 키와 구조 (최고 점수 등)
10. **파일 구조** — `/apps/element-gems/` 아래 파일 트리와 각 파일의 책임 (예: `index.html`, `style.css`, `game.js` 또는 모듈 분리). 파일이 너무 많아지지 않게 한다.
11. **구현 단계 분해** — Build 서브에이전트가 따를 순서 (보드 → 스왑/매치 → 중력/연쇄 → 점수/타이머 → 원소 스킬 → UI/연출 → 모바일 대응)
12. **검증 체크리스트** — Review 서브에이전트가 브라우저에서 확인할 항목 (PC/모바일 입력, 연쇄 정상 동작, 스킬 6종, 타이머, 종료/재시작, 콘솔 에러 없음)
13. **범위 밖(Non-goals)** 과 **리스크/열린 질문** — 사용자가 승인 시 결정해야 할 항목을 번호로 정리 (최대 5개)

## 작성 원칙
- 분량: 한국어로 간결하게. 표와 목록을 활용한다. 코드 전체를 쓰지 말고 필요한 경우 짧은 의사코드만 쓴다.
- 구현자가 추가 질문 없이 만들 수 있을 만큼 구체적으로 쓴다. (수치는 "초안 값"으로 명시)
- 막히거나 판단이 필요한 부분은 임의로 결정하지 말고 13번 '열린 질문'에 적는다.
