## 검증 항목
1. **spec §15.7, §16.5 체크리스트 전체**를 표(항목/결과/근거)로.
2. **2×2 규칙**: 단독 2×2 제거, 3×3 블록 그룹 크기 9, 2×2+3연속 겹침(그룹 합집합), 보드 가장자리·모서리, 서로 다른 색 인접 미매치, 연쇄 중(리필로 생긴) 2×2 제거, 초기 보드·재섞기 각 500회에서 매치 0·2×2 0·유효한 수 ≥1(Node에서 `game.js` 순수 함수로), `listMoves`/힌트가 2×2 수를 제안하고 실제로 매치되는지, 무효 스왑 되돌림, 점수·게이지·시간 보너스가 4매치와 동일, GOOD! 팝업 조건(4매치/2×2).
3. **난이도 3종**: 각 난이도로 시작해 시작 시간·상한·게이지 최대치(6색, aria-label)·시간 보너스·힌트(표시/쿨다운)·스킬 수치(물 정지, 어둠 지속, 빛 시간, 번개 제거 수)·점수 배율이 spec §15.2 표와 일치. 난이도 변경은 시작 화면에서만, 재시작은 같은 난이도·상태 초기화. 초보 자동 힌트(6초 무입력→4초 표시, 쿨다운 소모 없음), 중수·고수에는 없음. 경과 90초 이후 시간 보너스 ×0.5가 시간 정지·컷인·일시정지 구간을 경과에 포함하지 않는지.
4. **저장**: 옛 형식 데이터(`{best:1234,...}`)와 새 형식, 손상된 JSON/타입 오류, `localStorage` 차단 상황에서 에러 없이 기본값으로 동작, 난이도별 최고 점수 분리·NEW BEST 판정.
5. **귀여운 보석 이미지(`assets/gems/*.webp`)**: 64칸·게이지 6개 표시, 6종이 **모양으로 구분**되는지(스크린샷을 그레이스케일로 변환해 확인), 작은 화면(360×640)에서 식별 가능, 흰 보석(빛)이 보드 배경에서 잘 보이는지, 시작 화면 로고(`title-logo.webp`)의 보석 6개와 게임 보석이 같은 스타일인지, 선택/힌트/제거 연출에서 이미지가 깨지거나 흰 테두리(후광) 잔상이 없는지.
6. **회귀**: 스킬 6종 컷인→효과 1회, 컷인 중 타이머 정지, 일시정지/탭 숨김, 리셋, 시간 종료 정산, BGM·효과음 상태, 콘솔 에러·경고 0건, 에셋 404 없음, DOM/타이머 누수 없음.
7. **밸런스 재검증(제안만)**: Build 시뮬레이션(캐주얼 200판: 스킬 초보 10.2/중수 7.3/고수 4.6, 판 길이 100/81/61초)과 Plan 시뮬레이션(스킬 14.1/9.4/6.0, 판 길이 114/86/64초)이 약 25% 어긋난다. `game.js` 순수 함수로 **독립 시뮬레이션**(난이도당 300판 이상, 수당 생각시간·애니메이션 시간 반영, 가정 명시)을 돌려 spec §15.3 목표(스킬 초보 12~16 / 중수 8~11 / 고수 5~8, 판 길이 90~120 / 70~90 / 50~70초)와 비교하고, 어느 쪽 모델이 실제에 가까운지 근거와 함께 판단하라. 필요한 `CONFIG.difficulty` 조정안(예: 게이지 최대치 배율)을 **수치 제안으로만** 적는다.
