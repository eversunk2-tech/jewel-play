- 시간 보너스(3/4/5+매치): 초보 0.25/0.5/1.0, 중수 0.2/0.4/0.8, 고수 0.15/0.3/0.6, **경과 90초 이후 보너스 ×0.5**
- 게이지 최대치(불/물/풀/번개/어둠/빛): 초보 10/12/10/11/12/13, 중수 11/13/11/12/13/15, 고수 12/14/12/13/14/16
- 스킬 효과 수치(물 정지·어둠 지속·빛 +시간 등), 힌트 쿨다운은 난이도별 프리셋(§15.2)
- 한 판 스킬 사용 횟수 목표(60초대 기준): 초보 12~16 / 중수 8~11 / 고수 5~8, 판 길이 목표 초보 90~120초 / 중수 70~90초 / 고수 50~70초
- 스킬 사용 시 **컷인 연출 약 1.3초**(그동안 타이머 정지)가 나온다.

## 설계 방향 (세부 수치는 시뮬레이션으로 보정)
1. **시간 프리셋 3분화**: 중수 시작 시간 = **180초**. 난이도 차이는 비례 유지를 기본안으로: 초보 약 195초(3분 15초), 고수 약 150초(2분 30초). 더 좋은 안이 있으면 근거와 함께 제안.
2. **상한(max)**: 시작 시간 + 약 30초 수준을 출발점으로 정하되 시뮬레이션으로 확인.
3. **시간 보너스 감쇠 기준**: 현재 "경과 90초 이후 ×0.5"는 판이 3배가 되면 의미가 달라진다. 감쇠 시작 시점을 판 길이에 맞게(예: 약 270초 또는 시작 시간의 1.5배) 재설정하고, 보너스 크기도 한 판이 목표 길이에 끝나도록 보정한다. 숙련 플레이어가 판을 지나치게 늘리지 못하게 한다.
4. **스킬 횟수와 게이지 재보정(중요)**: 판이 3배 길어지면 같은 게이지 값으로는 스킬이 한 판에 약 3배(중수 약 27회) 나와 컷인 연출이 과해진다(컷인 합계 시간이 판의 큰 비중). 컷인 합계 시간과 플레이 리듬을 고려해 **스킬 횟수 목표를 새로 제안**하고(권장 출발점: 초보 약 18~22 / 중수 약 13~17 / 고수 약 9~12회), 이를 맞추도록 난이도별 게이지 최대치를 **재산정**한다. 단 원래 요청("게이지가 다 차는 데 성공 횟수가 너무 많이 필요하다")의 취지를 해치지 않게, 1회 스킬에 필요한 매치 그룹 수가 지금(초보 약 5 / 중수 약 6 / 고수 약 7)보다 과도하게 늘지 않는 범위에서 균형을 잡고, 트레이드오프를 표로 설명한다.
5. **판 길이 목표(캐주얼 중앙값)**: 초보 약 210~240초 / 중수 약 185~215초 / 고수 약 150~180초. 종료되지 않는 판이 없어야 한다(숙련 모델 포함 상한 내 수렴).
6. 컷인 시간(1.3초)이 판 길이에 미치는 영향(컷인 중 타이머 정지)을 시뮬레이션에 반영하거나 한계로 명시.
7. **UI 영향**: 타이머 표시 형식(60초 초과 시 `m:ss`, 예: 3:00), 타이머 바 비율(`남은시간/상한`), 시작 화면 규칙 문구 "제한 시간 N초" → "약 3분" 등 표기 규칙, 10초 이하 경고·효과음 `warning` 동작, 일시정지/종료 화면의 시간 표기, 난이도 설명 문구.
8. **그 외 영향 점검**: 빛 스킬 +N초·물 정지·어둠 지속 등 절대 시간 수치가 3분 판에서 상대적으로 약해지는지(조정이 필요하면 제안, 불필요하면 유지 사유), 힌트 쿨다운·초보 자동 힌트 시간, BGM(약 177초, 루프 재생)과의 관계, 칭찬 팝업 등 영향 없음 확인.

## 시뮬레이션 (필수)
`game.js` 순수 로직을 Node에서 불러 난이도별 **300판 이상**(캐주얼 모델: 수당 생각시간 약 1.6초 + 애니메이션 시간 반영, 컷인 중 시계 정지). 직전 시뮬레이션 간 불일치(Plan 측 vs Build 측 약 25%)가 있었으므로 **모델 가정(수당 시간, 스킬 효과 근사, 컷인 처리)을 명시**하고, 현재 값(60초 프리셋)을 먼저 재현해 보정 기준선으로 보고한 뒤 새 값으로 비교한다. 결과 표: 목표 vs 평균·중앙값·p10/p90(스킬 횟수, 판 길이, 스킬당 매치 그룹 수, 컷인 합계 시간). 숙련 모델(수당 약 1.0초)도 판 길이 상한 수렴을 확인.

7. 열린 질문(최대 4개)
