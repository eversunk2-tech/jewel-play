# Build 지침 U-A — 메뉴 화면 개선 V1 "풍경 속 타이틀": 시작·루트 선택·프로필·명예의 전당·교육용 단원 선택 (spec §32.4.1·§32.8·§32.9, 승인 기록 §34)

## 역할
너는 **Build 담당**(Sonnet 서브에이전트)이다. 사용자가 시안을 보고 고른 **V1 풍경 속 타이틀**을 **두 앱(일반용·교육용)과 루트 선택 화면**에 구현한다(CSS 중심 + 소규모 마크업). **게임 규칙·게임 화면(HUD·보드·보석·게이지·컷인·팝업·결과)·서버·저장은 한 글자도 바꾸지 않는다.** 이번 단계(U-A)는 U-1(시작·루트)·U-2(프로필·명예의 전당)·U-4(교육용 단원 선택·시작 화면 안내판)다. **레벨 선택 화면(U-3 카드 스킨)과 폰 세로·낮은 화면 마무리(U-5)는 다음 단계라 이번에 만들지 않는다**(레벨 선택은 지금 모양 그대로 두되, 배경 카메라 위치만 §32 토큰을 따를 수 있다). 검증은 별도 Review가 하며, **네가 직접 확인한 것만 "확인함"** 으로 쓴다.
프로젝트 규칙은 `CLAUDE.md`, 진행 상황은 `docs/STATUS.md` §14를 먼저 읽는다. **정답지는 `apps/element-gems/spec.md`의 §32(특히 §32.0·32.1·32.2·32.4.1 V1 표·32.7·32.8 점검표·32.9 단계·함정·32.12~)와 §34(승인 기록: V1 선택, 쉬어가기 표시 안 함, 글꼴 변경 없음)**. 줄 번호는 참고용이니 제목으로 찾는다.

## ⚠ 시안 파일이 없다 — 말로 다시 만든다
시안 때 쓴 CSS·스크립트·스크린샷(`scratchpad/plan-ui2/…`)은 재부팅 때 **지워져 없다**. §32.4.1(V1 표)·§32.2(현재 화면 감사 수치)·§32.7(측정)의 **글로 된 설명이 유일한 정답지**다. 숫자(로고 폭 684px, [시작] 495×99·글자 43px·외곽선 7px, 배경 `background-position`, 색 토큰)는 그대로 쓰고, 설명에 없는 세부(앞쪽 잎·햇살·친구 배치의 정확한 좌표)는 **스스로 설계**하되 "밝은 스카이 캔디·정글 그림·로고·젤리 보석" 정체성을 지키고 **구성·깊이·타이포 대비·움직임이 현재보다 눈에 띄게 달라지게** 한다(작은 미세 조정 금지, §32 머리말). 사용자가 아침에 보고 취향을 판단하므로 **스크린샷 번호표(현재 vs 새 것)**를 남겨라(아래 "확인할 것").

## 승인된 결정 (바꾸지 않는다)
- 시안 방향 = **V1 풍경 속 타이틀**. V2(좌우 분할)·V3(수첩)는 채택하지 않았고 **글꼴은 바꾸지 않는다**(글꼴 파일·`@font-face` 추가 금지, 시스템 글꼴 유지). **새 이미지·음원 파일 0개**(기존 `bg-jungle.webp`·`gems/*.webp`·`title-logo.webp` 재사용). 외부 URL·CDN 금지(`xmlns` 문자열 제외).
- 레벨 선택(U-3)은 다음 단계. **쉬어가기(3·6·9)는 화면에 표시하지 않는다**(§34).
- §34.2 잠정 기본값을 쓴다: **V2의 진행 10칸·난이도 타일 진행도는 이번에 가져오지 않는다**, 규칙 4항목은 **`? 게임 방법` 칩으로 접는다(첫 방문에는 펼침)**, 교육용 단원 선택은 **색·제목 토큰(리본 제목 + 큰 카드)만**, 일반용 동결 해제됨.
- **격리**: 새 CSS는 **전부 `.menu-screen`(또는 `#overlay-profile-ask`, 루트 선택 화면은 그 화면의 고유 클래스) 접두어**여야 하고 `#screen-game`·`.gem`·`.timer`·`.gauge`·`.board` 선택자를 포함하지 않는다. 배경 카메라(`html::before` 등 전역 요소)를 쓸 때는 **`:has(#screen-game:not([hidden]))`일 때 원래 위치로 돌아오게 가드**한다(§32.1·§32.9 함정 ④). 게임 화면의 계산 스타일은 변경 전과 같아야 한다(시험·측정).
- **두 앱 동일**: `style.css`는 두 앱이 **바이트 동일**이어야 하고(프로필·명예의 전당 구간은 소스까지 같음, 기존 시험이 검사), 교육용 전용 차이는 `edu.css`·교육용 `index.html`의 `[EDU]` 구간에만 둔다. 새 블록은 `style.css` **맨 끝**에 `/* 메뉴 V1 (spec §32, U-A) */` 하나로 붙인다(M4 정령 블록 뒤). 기존 규칙은 수정하지 않는다(필요한 한 줄 덮어쓰기는 새 블록 안에서 접두어로).
- 접근성: 글자 대비 WCAG AA(본문 4.5:1·큰 글자 3:1, **그림 위 글자는 실제 렌더 색으로 측정**), 터치 대상 ≥ 44px(주요 버튼 ≥ 56px), 색에만 의존하지 않음, `prefers-reduced-motion`이면 **모든 새 애니메이션·전환 0**, **무한 애니메이션은 화면당 ≤ 3**(§32.7.1), 보석 친구·장식은 `aria-hidden`, 포커스 표시·키보드 순서·`aria-*`는 기존 그대로(바꾸면 보고).
- 성능: `backdrop-filter`·`blur()` **금지**, 큰 `filter`는 배경 1레이어까지, `drop-shadow` 남발 금지. 첫 방문→첫 판 내려받기 증가는 **+10% 이내**(새 래스터 0이라 사실상 CSS·마크업 수십 KB). 외부 주소 0.
- 사용자 입력(닉네임·순위)은 **`textContent`로만** 채워진다는 기존 규칙을 해치지 않는다(`ranking-ui.js`는 읽기 전용, 마크업은 건드리지 않고 CSS `nth-child`·그리드로 시상대를 만든다).

## 만들 것
1. **토큰**(`.menu-screen` 범위 CSS 변수): 리본 `#6f57f7→#5b3df5`(흰 글자 4.79~6.12:1), [시작] 외곽선 `#8a3d00`(흰 글자 7.64:1), 큰 글자 레시피(흰 + 남보라/갈색 외곽선 + 아래 그림자, 게임의 칭찬 글자와 같은 문법), 잉크 `#2a2160`, 보조 `#5b5394`, **`border-radius` 값은 토큰 스케일(예 12·20·32·999px·50%)만 쓴다**(§32.8-6).
2. **배경 카메라**(P1): 같은 `bg-jungle.webp`가 화면마다 다른 곳을 비춘다 — 시작·루트 `50% 12%`, 레벨 선택 `50% 78%`, 프로필·명예의 전당·단원 선택 `50% 52%`(`.9s` 전환, **게임 화면은 원래 `center`**), 틴트 알파 .38→.12(하늘이 더 맑게). 햇살(정적 원뿔 그라디언트)과 앞쪽 잎(같은 그림 120vw 확대, 양 끝)은 `#app`의 `::before/::after`로 — **게임 화면에서는 `display:none`**.
3. **시작 화면**(일반용·교육용): 로고 **폭 684px 기준**(화면 폭의 58%, 작은 화면은 비율로 줄임), 보석 친구 6마리(기존 `gems/*.webp`, 58~160px, 크기·기울기 다르게, 로고 좌우, `aria-hidden`), 프로필 칩·진행(왼쪽 위)·명예의 전당(오른쪽 위)을 **모서리 칩**으로, 아래 가운데에 난이도 + **[시작] 495×99(글자 43px, 흰 글자+갈색 외곽선 7px)** + 한 줄 설명, **규칙 4항목은 `? 게임 방법` 칩(`<details>`·버튼 중 하나, 키보드로 열고 닫힘, `aria-expanded`)으로 접고 첫 방문에는 펼친다**(첫 방문 표시는 `localStorage` 별도 키 하나를 `try/catch`로 — 저장 구조 `save`와 무관, 실패하면 펼친 채로). 기능·버튼 id·순서(탭 순서)는 그대로.
4. **루트 `index.html`(교육용/일반용 선택)**: 로고 크게 + 햇살, 질문은 리본, 입구 카드 2장(±1.2° 기울임, 높이 276px 기준). 인라인 CSS라 해당 블록을 고친다. 교육용 직접 주소·선생님 안내는 넣지 않는다(CLAUDE.md).
5. **프로필 만들기/고치기**: 제목이 카드 위에 걸친 리본, 그림은 동그란 스티커, 고른 그림은 금빛 링 + 1.14배(색 외에 링·크기로 구분).
6. **명예의 전당**: **시상대** — 위 3명을 2·1·3 순서의 세 카드(1등은 가장 높고 금빛·아바타 100px·점수 1.9rem), 4위 이하는 2열 행, 내 순위 줄 아래 고정. 마크업은 바꾸지 않고 `nth-child`+그리드로. 순위가 3명 미만·0명일 때 깨지지 않는다(빈 상태·오프라인 폴백 포함).

8. **교육용 시작 화면은 일반용과 같은 V1 문법**이되 교육용 요소(학습 단원 카드·"선물상자 문제: 많이" 줄·`교육용` 리본)가 겹치지 않게 배치한다.

새 파일 `apps/element-gems/test/menu.test.js`·`apps/element-gems-edu/test/menu.test.js`: ① **격리**: 메뉴 블록의 모든 선택자가 허용 접두어로 시작하고 `#screen-game`·`.gem`·`.timer`·`.gauge`·`.board`를 포함하지 않음 ② 토큰 스케일: 메뉴 블록의 `border-radius` 값이 스케일 안 ③ 외부 주소 0·`backdrop-filter`·`blur(` 0·`@font-face` 0 ④ 두 앱 `style.css` 바이트 동일(기존 시험이 이미 있음) ⑤ 감소 모션 블록에 새 애니메이션이 전부 `none`이고, 무한 애니메이션 개수 ≤ 3 ⑥ 시작 화면 마크업: 기존 id·버튼·탭 순서 보존, `? 게임 방법`의 `aria-expanded`/접힘 동작(가짜 DOM), 보석 친구 `aria-hidden` ⑦ 루트 `index.html`: 새 블록, 선생님 안내·직접 주소 없음 ⑧ 새 에셋 파일 0개(`assets/` 변경 없음) ⑨ 게임 화면 가드: 전역 배경 요소의 게임 화면 규칙(`display:none`·원래 위치)이 CSS에 존재 ⑩ 문구에 피하는 말·"쉬어가기" 없음. **기존 시험의 `style.css` "맨 끝" 앵커는 내용 앵커로 옮기되 단언을 약화하지 않고 보고**(M4-A가 한 방식).
시험 기준값: 일반용·교육용·서버는 **작업 시작 시점에 직접 실행해 기록**하고(M4 직후 값) 끝날 때 새 값을 보고. 실패 0.
