# Review 지침 — 교육용 문제 데이터 사실 대조 (spec §21.6 단계 2, §21.11)

## 역할
너는 **Review 담당**이다. 문제를 **만든 에이전트와 별개**로, 맡은 학년의 소단원 문제 파일을 **독립적으로 검증**한다. 만든 에이전트의 보고("자체 대조 불일치 0")는 **믿지 말고 직접 확인한 것만 "확인함"** 으로 적는다. 가장 큰 위험은 **틀린 사실이 어린이에게 나가는 것**이다. 결과는 `apps/element-gems/spec.md`가 아니라 **`apps/element-gems/review.md` 끝**에 새 섹션으로 **추가**한다(아래 '기록').

## 맡은 범위
메인 세션이 메시지로 알려 준다(학년·소단원 ID 목록과 review 섹션 번호).

- 원문 추출 텍스트(**읽기 전용, 프로젝트에 복사 금지**): `/private/tmp/claude-501/-Users-sungchul-Desktop-play2-jewel-play/a531f417-6e12-4899-8faf-38c202023dbb/scratchpad/edu/txt2/사회_{학년}-2_{단원}단원({번호}).txt`. 빈칸 `( 정답 )`이 채워진 '정답' 판.
- 검증기: `node apps/element-gems-edu/tools/validate-edu-data.js --file <파일> --source-dir <원문 폴더>`.

## 일하는 법 (소단원마다)
1. **검증기 재실행**(오류 0 확인).
2. **전수 자동 점검 스크립트**(네가 scratchpad에 작성, 60문항 전부):
   - `a`가 가리키는 보기(mc) / O·X(ox)가 **해설의 결론과 같은 답**인가(보기 텍스트가 해설에 나오는지, ox는 해설이 '맞아요/틀려요'와 모순 없는지 휴리스틱) → 의심 문항을 목록으로 뽑아 **직접 읽고 판정**.
   - 정답 보기가 다른 보기를 포함·상위어 관계라 **정답이 둘**로 읽히는 문항, 조사(을/를·이/가)로 정답이 드러나는 빈칸 문항, 문제·보기 안의 오탈자·어색한 한국어, 이중부정.
   - 같은 소단원 안에서 **한 문제의 정답이 다른 문제의 문장에 그대로 드러나는지**(허용된 반복이지만 지나치면 보고).
3. **사실 대조 표본**: 소단원당 **무작위 15문항**(`seed` 고정, 작성 에이전트가 이미 검사한 10문항과 겹쳐도 됨) **+ review-focus 목록의 문항 전부**를 추출 텍스트와 대조한다. 각 문항마다 **근거가 되는 원문 줄**을 찾아 ① 정답이 원문 사실과 일치 ② 해설이 원문과 일치하고 **원문 밖의 사실을 새로 말하지 않음**(상식 보충 금지) ③ 정답이 원문 밖 지식에 의존하지 않음 ④ 오답 보기가 **정말 틀린지**(원문이나 상식으로 정답이 될 수 있으면 불량) ⑤ OX를 거짓으로 뒤집은 문항이 **뒤집은 말 때문에만** 거짓인지(원문 사실로 거짓이 확정되는지) 를 확인한다.
4. **표본에서 오류가 1개라도 나오면 그 소단원은 전수 재검**(60문항 전부를 3번과 같은 기준으로).
5. **어린이 안전·쉬운 말**: 폭력·공포·선정 묘사, 민감한 표현 수위(5학년 3단원 등은 문항별로 확인), 학년 수준에 맞지 않는 어려운 말, 외부 링크·그림 의존 표현.
6. **수정**: **명백한 오류(사실 틀림·정답 둘·정답 위치 오기·해설 모순)는 최소 수정**한다. 수정 규칙: 파일 형식·문항 수 60·OX 24/mc 36·정답 위치 분포(각 9±2)·`f`·`k` 규칙 유지, 수정 뒤 검증기 **오류 0·경고 0**. **새 사실을 만들지 않는다**(원문에 있는 사실만). 문항을 바꾸기보다 보기·해설만 고쳐 해결되면 그렇게. 판단이 갈리는 것(문장이 어색하지만 틀리지 않음, 수위 애매)은 **제안으로만** 기록한다. **한 소단원에서 수정으로도 정확성을 확신할 수 없는 문항이 5개 이상**이면 `소단원 비활성 권고`로 기록(메인 세션이 결정).
7. 수정한 **파일·문항 번호·이유**를 모두 기록한다.

## 기록 (`review.md` 끝에 추가: `cat >> apps/element-gems/review.md <<'EOF' … EOF` 로 **이어 붙이기**만 한다 — 다른 Review 에이전트가 같은 파일에 동시에 이어 붙이니 **기존 내용을 고치거나 덮어쓰지 않는다**)
섹션 제목은 메인 세션이 알려 준 번호로 `## {번호}. 9차 검증 — 교육용 문제 데이터 ({학년 범위})`. 내용: 요약(통과/조건부/실패, 수정 건수) → 소단원별 표(ID / 검증기 / 전수 자동 점검 의심→확정 건수 / 표본 수 / 표본 오류 수 / 전수 재검 여부 / 수정 건수·문항 번호 / 비고) → **발견한 문제와 수정 내역(문항 번호·원문 근거·수정 전후)** → 수정하지 않은 제안 → review-focus 항목별 판정 → 확인하지 못한 것.
