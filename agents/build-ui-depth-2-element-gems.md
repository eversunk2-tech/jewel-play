# Build 추가 지침 2 — 상태 색 복원(덮임 결함 수정) (spec §49, `agents/build-ui-depth-element-gems.md`의 후속)

작성: 2026-11-21 (메인 세션). 모델: Sonnet. **1차 Build 지침의 안전 규칙·파일 소유권·검증 방법은 그대로 유효**하고, 아래는 **추가 변경**이다(충돌하는 부분은 이 문서가 대체: "CSS는 시안 그대로" 원칙에 **아래 "상태 색 복원 블록"만 예외**).

## 배경 (메인 세션이 직접 확인한 것)
1차 Build 보고 ⑥ A에서 발견된 **의도하지 않은 덮임**: `:root .m-chip`, `:root .learn-chip`, `:root #end-title` 등 시안 규칙의 우선순위가 원본 상태 규칙(`.m-chip.done`·`.learn-chip.done`·`#end-title.clear`)과 **같고 `ui-depth.css`가 나중에 로드돼 이겨서**, 완료·클리어 상태의 색이 사라졌다(원본: 완료 칩 = 초록 그라데이션, STAGE CLEAR = 호박색 그라데이션). 시안 촬영 때 상태 화면을 찍지 않아 못 본 **결함**이다. 이 변화는 B-1의 의도가 아니므로 **원래 상태 색을 되살리는 최소 수정**을 한다(사용자 승인 범위 안의 결함 수정). 같은 종류 결함이 더 있는지 **전수 검사**도 한다.

## 할 일
### 1. 상태 색 전수 검사(수정 전에 먼저, 결과를 보고)
원본 `style.css`·`edu.css`에서 **상태를 나타내는 선택자**(클래스·속성: `.done`·`.clear`·`.cleared`·`.current`·`.locked`·`.on`·`.right`·`.wrong`·`.mine-wrong`·`.frozen`·`.dark`·`.full`·`.aiming`·`.cooling`·`.is-chal`·`.top1`·`.me`·`.plain`·`.special`·`[data-kind]`·`[aria-expanded]`·`[aria-checked]`·`[aria-selected]`·`[aria-pressed]`·`:disabled`·`[disabled]` 등, 실제 목록은 두 CSS를 읽어 직접 뽑는다)를 모두 찾아, **그 상태 규칙이 `background`·`background-image`·`background-color`·`color`·`border-color`를 정하는 경우**마다 실제 브라우저 사본(전 = `git archive HEAD` 사본, 후 = 현재 작업 트리 사본)에서 **해당 상태의 요소**(없으면 같은 기본 요소에 클래스/속성을 붙여 강제)의 계산된 값 `background-image`·`background-color`·`color`를 전·후로 비교해 **바뀐 것을 표로** 낸다. B-1이 **의도적으로 바꾼 기본 면**(예: 일반 `.btn`·`.m-chip`의 기본 트랙색, 정보 줄 면)은 상태가 없는 요소에서만 달라야 하고, **상태 요소의 색은 달라지면 안 된다**(받침(블러 0 오프셋 그림자)만 사라지는 것이 정상). 결과 표에서 "의도하지 않은 덮임"을 모두 골라 낸다. 지금까지 알려진 후보: `.m-chip.done`, `#end-title.clear`, `.learn-chip.done`, `#btn-howto[aria-expanded="true"]`(=`.howto-btn[aria-expanded]` 펼침). 그 밖에 나오면 같이 처리.

### 2. 최소 수정: `ui-depth.css` 끝에 "상태 색 복원" 블록 하나 추가
- **기존 시안 규칙은 한 글자도 바꾸지 않는다**(선택자에 `:not()`을 붙이는 식의 수정 금지). 대신 파일 **맨 끝**(`@keyframes`·`@media` 블록들 앞이든 뒤든 한 덩어리로, 앞에 `/* ---------- 상태 색 복원(spec §49.9 보충): 시안 규칙이 원본 상태 색을 덮은 곳을 되살림 ---------- */` 주석)에 규칙을 **추가**한다. 모든 선택자 `:root ` 접두어, `!important` 0, **받침 금지**(원본 상태 규칙에 `0 Npx 0` 받침이 들어 있는 경우(예: `.learn-chip.done`의 `0 3px 0 …`)에는 **원본 그림자를 복사하지 말고** B-1 문법의 링·확산 그림자(시안 변수 `--dp-hl`·`--dp-ring-*`·`--dp-sh-*`)로 쓴다), 레이아웃 선언 0.
- 되살릴 값은 **원본 상태 규칙의 배경(그라데이션)·글자색 그대로**(복사). 예: 완료 칩 = `linear-gradient(180deg, #d4fbe6 0%, #a8f0c8 100%)`·글자 `#0d3b24`, STAGE CLEAR = `linear-gradient(180deg, #ffe97a, #ffb21a)`·글자 `var(--accent-ink)`(시안이 이미 `#end-title.clear`의 링 그림자는 정해 두었으니 **배경만** 되살린다), 게임 방법 펼침 = 원본 펼침 면색. 링 색은 면 색 계열(예: 완료 칩 `rgba(15, 122, 67, .35)`)로, 정보 줄 링 강도(`--dp-ring-i`)와 비슷하게.
- **`.howto-btn:focus-visible`의 흰 6px 고리 복원**(보고 ⑥ B): `:root .menu-screen .howto-btn:focus-visible { … 시안의 호버 그림자 변수들 …, 0 0 0 6px #fff }` 식으로 한 줄 추가(원본 `.menu-screen .howto-btn:focus-visible { outline: 3px solid var(--focus); outline-offset: 3px; box-shadow: 0 0 0 6px #fff; }`의 흰 고리와 같은 효과). 3px 윤곽선은 그대로 둔다.
- **보고 ⑥ C(`.eg-chip:active`·`.eg-amt:active`가 눌리는 순간 고른 칸의 고리를 약하게 덮음)는 이번에 고치지 않는다**(눌리는 순간만, 시험의 명시 예외로 유지; 제안으로만 남긴다).
- 1번 전수 검사에서 더 나온 결함은 **같은 방식으로 이 블록에 추가**하되, 어떤 것을 추가했는지 표로 보고한다. 판단이 애매한 것(B-1이 의도적으로 바꾼 상태 면인지, 덮임인지)은 **추가하지 말고 보고**한다.

### 3. 시험 확장
- 기존 26개 시험은 **지우거나 약화하지 않는다**. 규칙 ①~⑫가 새 블록에도 그대로 적용되는지(`:root` 접두어·받침 0·레이아웃 0·`!important` 0·알파 ≥ .96 배경 규칙 등) 확인한다. 규칙 ⑫(배경 맨 아래 층 알파 ≥ .96)는 되살린 원본 그라데이션에도 통과해야 한다.
- **새 시험 추가(두 앱 같은 내용)**: ⑬ **상태 색 복원 블록이 존재**하고 복원 대상 선택자 목록(`.m-chip.done`·`.learn-chip.done`·`#end-title.clear`·게임 방법 펼침 + 전수 검사에서 추가된 것)을 포함, 각 규칙의 `background`가 **원본 CSS의 해당 상태 규칙 `background`와 같은 문자열**(원본 `style.css`/`edu.css`를 읽어 비교 — 원본이 바뀌면 시험이 알려 주도록), 블록 안에 받침 0. ⑭ `.howto-btn:focus-visible` 복원 규칙에 `0 0 0 6px #fff` 포함. 각각 **변이 시험**(복원 블록 삭제·배경 한 글자 변경·받침 추가)으로 실패하는지 확인한다.
- 새 시험 수 n′와 변이 결과를 보고한다.

### 4. 다시 검증(1차 Build 지침 검증 1~5와 같은 방식)
시험 전체(일반용 368 + n′, 교육용 635 + n′(건너뜀 1), 서버 126), `validate-edu-data.js`, `build.js --check`, 읽기 전용 파일 해시, `cmp`(두 앱 `ui-depth.css`·`depth.test.js` 바이트 동일), **받침 후보 0·레이아웃 이동 0·`backdrop-filter` 0·번짐 0%·글자 전수 스캔 새 미달 0**(하니스, 1차와 같은 값이 나와야 함). 그리고 **상태 화면 전·후 크롭**: 미션 칩 완료(점수형이 아닌 미션 레벨 진행 중 완료된 목표), 결과 STAGE CLEAR, 교육용 선물상자 문제 칩 완료, 게임 방법 펼침·포커스를 **좌우 비교표**로 만들어 "원래 색이 돌아왔다"를 눈으로 확인하고 경로를 보고한다. 머리 주석의 "시안 그대로" 문구는 "규칙은 시안(B-1)과 같고, 끝의 '상태 색 복원' 블록만 추가"로 정정한다. 시안(`ui-depth-BG.css`)과의 **주석 제거 후 차이가 추가한 블록뿐**임을 diff로 보인다.
