## 검증할 것 (표로 판정)
1. **표가 §36 그대로인가**: scratchpad `plan-mission-m2/m2-tables.json`과 `CONFIG.stages.missions`를 **JSON 비교**(글자 그대로 같은지). `goalType`이 `{easy:'score', normal:'mission', hard:'mission'}`, 초보에는 표가 없음, `missionValid` 20칸 통과, 비-SEQ 칩 ≤ 2·SEQ ≤ 4, SEQ는 5·10단계뿐, 색 번호 0~5, `targets`(점수 폴백) 값이 직전 커밋 `b65b387`과 같은지, `special [5,10]`·`rest [3,6,9]`.
2. **재보정 표의 클리어율을 새 시드로 다시 잰다(최우선 수치 항목)**
   - **엔진은 작업 트리의 실제 `apps/element-gems/game.js`**(가짜 DOM + 가상 시계 하네스. Plan이 쓴 `…/scratchpad/plan-mission-m2/work/`의 `h.js`·`bot.js`·`pool.js`·`worker.js`·`sim.js`·`val.js`가 **읽기 전용 참고**다 — 그대로 믿지 말고 `review-mission-m2/`로 **복사해** 스냅샷 대신 작업 트리 `game.js`를 읽도록 바꾸고 네가 검토한다. 하네스 자체가 맞는지는 아래 3번으로 확인한다).
   - **새 시드는 40,000,000 이상**(Plan이 쓴 보정 구간 10,000,000~29,795,299와 검증 구간 11,000,000~·11,500,000~과 겹치지 않게; 겹침 여부를 계산으로 보고서에 적는다). **셀당 800판 이상**(기준 플레이어 D·H는 1,200판 권장).
   - 플레이어(정의는 spec §36.2): 기준 **D**(중수)·**H**(고수), 그리고 A·B·C·E·F·G와 긴꼬리 Dlt·Hlt를 중수·고수 모두에. 초보(점수)는 기준 P0·C·D·E·G를 한 번.
   - 판정: 기준 플레이어 클리어율이 §27.4 곡선(중수 D: 95·90·94·84·72·80·66·58·68·38, 고수 H: 90·82·88·74·60·70·54·46·58·28)에서 **±5%p**인지. §36이 예외로 적은 고수 2·4단계는 그 사실을 알고 판정하되 **새 값을 그대로 적는다**. ±5%p를 넘는 칸이 있으면 **어떻게 바꾸면 되는지(칸별 새 값 후보와 그 클리어율)** 를 수치로 제안한다(**표는 네가 바꾸지 않는다** — 메인 세션이 결정).
   - 톱니(3·6·9단계가 앞 레벨보다 +4%p 이상 쉬움, 5·10단계는 앞 레벨보다 어려움), 난이도 순서(같은 플레이어·같은 레벨 번호에서 초보 ≥ 중수 ≥ 고수, 위반 수), "벽"(H가 어느 레벨에서든 25% 아래로 내려가는지), 별 분포(기준 플레이어, §36.7과 비교)도 적는다.
3. **하네스·엔진 동등성 증명(네가 직접)**: (a) 같은 시드를 두 번 돌려 결정적인지. (b) **작업 트리 `game.js`와 Plan의 스냅샷(`plan-mission-m2/snapshot/apps/element-gems/game.js` = git `b65b387`)이 미션 카운트 규칙에서 같은가** — `git diff`로 `awardGroup`·`runAction`·`missionUpdate`·`missionInit` 쪽 변경이 **주석뿐인지** 한 줄씩 보고하고, 같은 시드·같은 봇으로 두 파일을 중수·고수 미션형으로 각 ≥ 150판 돌려 클리어 여부·최종 카운터가 판마다 일치하는지(불일치 0)를 확인한다(스냅샷의 `goalType`은 하네스에서 `mission`으로 덮어쓴다). (c) 초보 레벨에서 작업 트리가 `b65b387`과 판 단위로 같은지(≥ 45판, 보드·점수·시간·통계·저장 JSON·`Math.random` 호출 수). (d) **롤백 스위치**: `goalType.normal/hard = 'score'`로 두면 `b65b387`(M1 직후, 점수 목표)과 같은 판이 되는지(≥ 60판). (e) 음성 대조(하네스를 일부러 어긋나게 해 불일치로 잡히는지).
4. **레벨 카드 마크업 계약(§32.5.4)·설명판(§27.9 M2)**: 카드 `data-kind`(`special`/`rest`/``), `.sc-tag` "특별"은 **미션형으로 켜진 중수·고수 5·10단계에만**, 초보에는 없음; `aria-label` 형식("레벨 7, 미션 번개 보석 30개 그리고 연쇄 9번, 별 0개" / 특별 "레벨 5, 특별 레벨, 미션 먼저 …, 그다음 …" / 잠김은 맨 끝 "잠김" / 점수 카드 "레벨 3, 목표 N점, 별 0개"); **"쉬어가기"·"쉬어" 글자가 화면·`aria-label`·`title`·`index.html`·도움말 어디에도 없는지**(전수 검색), 폭력 연상어(전투·공격·처치·파괴·적·보스·체력·데미지 등) 없음. `#stage-detail`: 현재 레벨 표시, `focusin`·마우스 `pointerover`로 갱신, **터치 `pointerover`는 무시**, `aria-live` 없음, 잠긴 레벨은 잠김 안내만, 난이도 바꿀 때·레벨 클리어 뒤 목록 다시 그릴 때·"다시 하기"·메뉴 왕복 뒤에 설명판이 **옛 난이도의 글을 남기지 않는지**, `[도전!]`(`#btn-stage-go`)이 잠긴 레벨에서 무엇을 하는지, 키보드만으로(Tab/Enter/Space) 레벨 선택→설명판→도전이 되는지, 초보에서는 "목표 점수 N점"만 나오고 미션 문구가 없는지. 규칙 문구 `#rule-stage`가 중수·고수 미션형일 때와 폴백일 때 맞는 말인지.
