# Plan 서브에이전트 지침 — element-gems UI 리디자인 (최신 모바일 게임 스타일)

## 역할
너는 **Plan(디자인 기획) 담당**이다. 프로젝트 코드를 구현하지 않는다. 산출물은 ① spec.md의 **§18 UI 리디자인** 섹션, ② 시안 확인용 **목업 HTML과 스크린샷**(scratchpad)이다.

## 수정 가능 범위 (엄수)
- `/Users/sungchul/Desktop/워크숍/apps/element-gems/spec.md` — **끝에 `## 18. UI 리디자인` 추가만**. 기존 섹션은 고치지 않는다.
- 목업 파일과 스크린샷은 현재 세션 **scratchpad 디렉터리에만** 만든다(프로젝트 폴더에 남기지 않는다). 목업이 에셋 이미지를 쓰려면 scratchpad로 **복사**해서 쓴다.
- `index.html` / `style.css` / `game.js` / `assets/` / `review.md` / `CLAUDE.md` / `agents/` / `PRD.md` 는 **읽기 전용**(지금 다른 Review 에이전트가 코드를 검증 중이므로 절대 수정 금지). 커밋/푸시 금지.
- 브라우저를 쓸 때는 **새 탭**을 만들고 모든 호출에 `tabId`를 명시한다. 로컬 `file://` 또는 로컬 서버만 사용한다(배포 주소와 기존에 열린 탭은 건드리지 않는다).

## 사용자 요청 (원문 요지)
"게임의 전체 프레임이 너무 올드한 느낌이다. **최신 유행하는 휴대폰 게임들의 디자인 요소를 분석**해서, **메인 화면 배경 및 글자 등의 색상과 디자인, 보석 배경 사각형 모든 칸들의 디자인 및 색상적 요소들**도 업그레이드해 줘."
- 대상: ① 메인(시작) 화면 배경·글자·버튼·카드 ② 게임 화면 전체 프레임(HUD, 타이머 바, 점수/목표 바, 보드 프레임) ③ **보드의 64개 칸 각각의 디자인과 색상** ④ 게이지 버튼·하단 버튼 ⑤ 레벨 선택 화면·결과/일시정지 오버레이.
- 현재 느낌: 어두운 보라 유리 패널 + 금색 테두리 + 갈색 체크무늬 + 사실적 정글 배경 = "구식". 귀여운 캐릭터 보석(파스텔 젤리 질감)과도 톤이 맞지 않는다.

## 해야 할 일
### 1. 트렌드 분석 (웹 조사)
- 최근 인기 모바일 캐주얼/퍼즐 게임(예: 매치-3 퍼즐, 하이퍼캐주얼 포함)의 UI 디자인 요소를 **웹 검색으로 조사**한다(WebSearch 사용 가능하면 사용, 불가능하면 지식 기반으로 하되 그 사실을 명시). 상표·고유 에셋을 그대로 베끼지 않고 **일반적 디자인 패턴**(색 구성, 질감, 형태, 타이포그래피, 모션, 아이콘/버튼 스타일, 보드·타일 처리, 배경 구성)만 추출한다.
- 결과를 표로: 요소 / 최신 트렌드 / 현재 우리 UI / 개선 방향.
- 초등학생 대상 + 귀여운 캐릭터 보석과의 **일관성**을 기준으로 취사선택한다.

### 2. 디자인 방향 제안 (3안 → 1안 추천)
- 서로 뚜렷이 다른 컨셉 3안(예: ① 밝은 파스텔 캔디 월드, ② 반짝이는 보석 왕국/하늘 섬, ③ 네온 글로우 다크)을 간단히 제시하고 **추천안 1개**를 근거와 함께 정한다. 각 안은 배경 컨셉, 메인 컬러/보조 컬러/강조색, 분위기 한 줄.

### 3. 추천안의 상세 디자인 스펙 (구현자가 추가 질문 없이 만들 수 있게)
- **디자인 토큰**: CSS 변수 목록(배경/표면/텍스트/강조/성공/경고/그림자/반경/간격), 원소 6색의 UI 강조색(게이지·컷인·팝업에 공통 사용), **명도 대비 WCAG AA(텍스트 4.5:1) 충족** 수치 검증 결과.
- **타이포그래피**: 폰트 선택(한글 지원, 둥글고 굵은 게임풍). 외부 CDN 폰트(Google Fonts 등)를 쓸지 시스템 폰트 + 굵기/외곽선 처리로 갈지 **장단점과 권장**(오프라인·로딩·`file://`·저작권). 크기/굵기/자간 스케일, 글자 외곽선(stroke)+그림자 레시피.
- **메인(시작) 화면**: 배경 구성, 로고 배치, 난이도 버튼(선택/비선택 상태), 시작 버튼, 규칙 카드, 토글 버튼의 형태·색·그림자·상태(hover/active/disabled).
- **게임 화면 프레임**: 타이머 바, 점수/목표 진행 바, 난이도·레벨 칩, 보드 프레임, 게이지 버튼 6개(채움/가득참 펄스), 힌트/메뉴/리셋 버튼.
- **보드 64칸 디자인(핵심)**: 칸 모양(둥근 사각형 반경, 간격), 색(교차 타일 2톤 vs 단색 + 은은한 패턴 등), 질감(유리/젤리/소프트 그라디언트/안쪽 그림자·하이라이트), 보석과의 대비(흰 보석 포함 6종 모두 식별), 선택/힌트/매치 시 칸의 상태 표현, 보드 전체 프레임·배경(블러 유리 등). 성능을 위해 칸 수(64)가 많으므로 **무거운 필터(blur, 큰 drop-shadow)를 칸마다 쓰지 않는** 구현 방식 제안.
- **레벨 선택 화면 / 결과·일시정지 오버레이 / 칭찬 팝업 / 컷인 말풍선과의 톤 정합**.
- **모션**: 화면 전환, 버튼 눌림, 별 획득, 목표 바 채움 등 가벼운 마이크로 인터랙션(`prefers-reduced-motion` 대응).
- **새 이미지 에셋이 필요한 항목**과 **Gemini 이미지 생성 프롬프트 초안**(예: 새 메인 배경 세로 9:16, 구름/섬/반짝임 레이어, 보드 프레임 장식 등). 에셋 없이 CSS만으로 가능한 것과 구분. 용량 예산(전체 에셋 증가분 ≤ 1MB 권장).
- **유지해야 할 것**: 보석 6종의 모양 구분(색약 대응), 터치 타깃 ≥ 44px, 360×640~1280×800 반응형, 현재 기능·레이아웃 동작(수치·규칙 불변), 저사양 기기 성능.

### 4. 목업 (필수)
- scratchpad에 **자체 완결 목업 HTML**(추천안 기준)을 만들고, 현재 프로젝트의 CSS 구조와 **같은 요소 구성**으로 최소 3화면을 렌더링한다: ① 메인(시작) 화면 ② 게임 화면(8×8 보드, 보석 이미지, HUD, 게이지) ③ 레벨 선택 화면. 보석은 `assets/gems/*.webp`를 scratchpad로 복사해 사용.
- 390×844 뷰포트에서 **스크린샷을 저장**한다(scratchpad). 현재 화면(before)과 목업(after)을 비교할 수 있게 같은 뷰포트의 현재 화면 스크린샷도 저장한다(로컬 서버로 프로젝트 폴더를 읽기만 하는 서버를 scratchpad에서 띄워 촬영, 끝나면 서버 종료).
- 스크린샷 절대 경로를 완료 보고에 적는다.

### 5. 구현 계획
- 변경 대상 파일/선택자 목록(`style.css` 중심, 필요한 `index.html` 마크업 변경), 영향받는 JS 클래스/DOM(최소화), 단계 분해(Build용), 검증 체크리스트(Review용: 대비 측정, 6종 보석 식별, 칸 상태 표현, 360~1280 레이아웃, 성능(저사양 프레임), 기능 회귀 없음, `file://`/CDN 폰트 로딩 실패 시 폴백).
- 열린 질문(최대 5개): 컨셉 선택, 폰트 방식, 새 배경 이미지 생성 여부, 컷인 캐릭터를 귀여운 스타일로 맞출지 등.
