작성: 2026-11-21 (메인 세션). 모델: Sonnet. **1차 Build 지침(`agents/build-ui-depth-element-gems.md`)·추가 2(`agents/build-ui-depth-2-element-gems.md`)의 안전 규칙·파일 소유권·검증 방법은 그대로 유효**하다. 근거: Review R-D(`apps/element-gems/review.md` §40)의 제안 D9·D8, 그리고 **사용자 결정(2026-11-21, 질문 도구 답)**: 교육용 선물상자 문제 칩은 *"크림색으로 복원"*(권장안 선택).

## 현재 상태(메인 세션이 직접 확인)
`ui-depth.css`(두 앱 바이트 동일, 22,440B)는 시안 규칙 82덩어리 + 끝의 "상태 색 복원" 블록(Build 7 + Review 3 = 추가 10규칙). 시험 일반용 374·교육용 641(건너뜀 1)·서버 126 통과. **기존 시안 규칙은 한 글자도 바꾸지 않는다**(이번에도 끝 블록에 규칙을 **추가**하는 방식만).

## 할 일 (정확히 이 둘, 그 밖의 변경 금지)
### 1. D9 — 교육용 `.learn-chip` 기본(비완료) 면을 원래 크림색으로 복원
- 원본 `edu.css`의 `.learn-chip`(기본 면) 배경·글자색을 읽어 확인한다(전 = HEAD 사본에서 계산된 값도 확인). 시안 규칙 `:root .learn-chip`(정보 줄 그룹, 흰→연하늘)이 이를 덮고 있다.
- 복원 블록에 `:root .learn-chip`을 **원본 크림 그라데이션(원본 배경 문자열 그대로)**으로 되살리는 규칙을 추가한다. **불투명**(알파 ≥ .96)이어야 하고, 원본 그림자에 받침(`0 Npx 0`)이 있으면 **복사하지 말고** B-1 문법(`var(--dp-hl)` + 크림 계열 1px 링 + `var(--dp-sh-a)` 등, B-1이 교육용 단원 카드 `.eg-unit`에 쓰는 크림 규칙의 링 색·강도를 참고)으로 쓴다. `background-origin: border-box` 짝, `:root ` 접두어, `!important` 0, 레이아웃 선언 0.
- **이미 복원돼 있는 완료 상태(`:root .learn-chip.done`, 초록)가 계속 이기는지**(우선순위·순서) 계산된 스타일로 확인한다(완료 칩이 다시 크림으로 덮이면 실패). 글자색·`.lc-fill`·`.lc-ok` 불변.
- 시험(두 앱 같은 내용): 규칙 ⑬ 목록·원본 배경 문자열 일치 검사에 이 규칙(`.learn-chip` 기본)을 포함하고 변이 시험(규칙 삭제·배경 한 글자 변경·받침 추가)으로 잡는지 확인한다. 기존 시험 단언은 지우거나 약화하지 않는다.

### 2. D8 — `#eg-amount-desc` 글자 대비 4.32 → ≥ 4.5 (WCAG AA, 프로젝트 규칙)
- Review가 "새 미달 1: `#eg-amount-desc`, 최저 4.32"로 보고했다(전(HEAD)에서는 미달이 아니었는지 **먼저 직접 확인**). 원인이 시안 규칙이 바꾼 **면 색**인지 **글자색**인지 계산된 값으로 확인하고, **가장 작은 수정**(해당 요소 글자색을 한 단계 진하게 하는 규칙 한 줄을 복원 블록에 추가 — 색은 같은 색상 계열, 다른 곳에 영향이 없게 `#eg-amount-desc`만 선택)으로 고친다. 수정 후 이 요소의 대비를 **면 색 최악(그라데이션 가장 어두운 곳) 기준**으로 계산해 ≥ 4.5(권장 ≥ 4.8)임을 보인다.
- 같은 방식의 **다른 새 미달이 없는지**(두 앱 글자 전수 스캔, Review의 875개 방식 또는 하니스 `textscan.mjs`)를 다시 확인해 보고한다(★ 장식 2는 기존과 같음).
