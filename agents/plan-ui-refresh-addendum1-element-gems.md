# 추가 지침 1 — 사용자 정정(2026-11-08): 대상은 **게임 플레이 화면이 아니라 메뉴 페이지들** (원 지침의 범위를 **대체**)

원 지침: `agents/plan-ui-refresh-element-gems.md`. 충돌하면 **이 문서가 우선**이다. 이미 쓴 §29 내용·시안은 이 범위에 맞게 고치거나 버린다(§29는 네가 쓰는 §이니 고쳐도 된다. §1~§28은 읽기만).

## 사용자 말 (원문)
"**게임 플레이 시 UI는 완전히 괜찮아.** 처음 **교육용, 일반용 선택**부터 **메인메뉴를 비롯한 메뉴들 페이지**를 말하는 거야."

## 범위 (원 지침의 화면 목록을 이것으로 대체)
**대상(IN)** — "AI가 만든 느낌"을 걷어낼 메뉴 계열 페이지 전부:
- 저장소 루트 `index.html`의 **교육용/일반용 선택 화면**(선택 화면에는 선생님 안내·직접 주소를 두지 않는 기존 규칙 유지)
- **시작 화면/메인 메뉴**(`#screen-start`: 로고, 난이도 3버튼, 시작 버튼, 설정·규칙 안내 등) — 일반용·교육용 둘 다(교육용의 홈/모드 선택/학습단원 고르기 포함)
- **레벨 선택**(`#screen-stages`)
- **프로필 만들기**(`#screen-profile`)와 **명예의 전당**(`#screen-hall`), 이 화면들이 쓰는 확인창
- 그 밖에 메뉴 성격의 화면·팝업(설정, 사용법, 교육용 학습단원 선택 화면 등)이 있으면 코드에서 찾아 포함

**제외(OUT) — 바꾸지 않는다**: 게임 화면(`#screen-game`)의 **HUD(타이머·점수·목표 바·게이지)·보드·보석**, **컷인**, 게임 중 **선물상자(?) 문제 팝업**. 이것들은 사용자가 "완전히 괜찮다"고 한 부분이므로 감사·시안에서 바꾸지 않고 **기준(바꾸지 않는 이웃)**으로만 쓴다.
**경계(열린 질문으로 올릴 것)**: **결과 오버레이**(클리어·실패 팝업)는 게임 직후 화면이라 기본은 제외하되, 메뉴와 같은 카드·버튼 문법을 쓰므로 "함께 다듬을지"를 열린 질문 1개로 올리고 권장안을 적는다.

## 이 범위에서 달라지는 요구
1. **감사·시안**: 위 IN 화면만 새로 렌더링해 감사하고 시안을 만든다(폰 세로, 대표 1화면은 PC 폭, 교육용 화면 포함). 게임 HUD 시안은 **만들지 않는다**. 대신 **"메뉴 → 게임 시작" 전환 장면 한 쌍**(메뉴 마지막 화면과 게임 첫 화면)을 안마다 찍어 **바뀌지 않는 게임 화면과 메뉴가 이질감 없이 이어지는지** 보여 준다.
2. **일관성 제약**: 게임 화면은 그대로 두므로 안의 색·외곽선·글꼴·그림자 문법은 **게임 화면과 한 세트로 보여야** 한다. 공용 토큰(`style.css`의 `:root` 변수 등)을 바꿀 때는 **게임 화면에 번지지 않는지**(메뉴 전용 클래스·변수로 한정하는 방법) 확인하고, 게임 화면 CSS는 건드리지 않는 설계를 기본으로 한다.
3. **인기 게임 분석 범위**: 홈/타이틀, 모드·난이도 선택, 레벨 맵, 프로필·랭킹·리더보드, 설정 화면의 구성·위계·타이포·아이콘·버튼 문법·마스코트 사용에 집중한다. HUD·매치 연출 분석은 참고 수준으로만.
4. **충돌 표**: 가장 큰 접점은 **§27의 레벨 카드(미션 요약·난이도 계단·톱니 곡선 표시)와 레벨 선택 화면**이다. §27 M1·M2 Build가 레벨 선택 화면을 바꾸므로 **순서(메뉴 개선을 먼저/나중)**를 권장과 함께 표로 쓴다. §28은 게임 중 점수 표기라 거의 무관하다(결과 화면·최고 점수 표시만 확인).
5. **AI 느낌 점검표**도 메뉴 화면 기준으로 만든다. 메뉴는 정적이므로 **마스코트·세계관 배경·타이포·아이콘·질감·위계·모션(진입/눌림/대기)**을 개선 레버로 비교하되, 게임 화면의 젤리 보석·로고 톤은 보존한다.
6. **Build 단계 분해**: 1단계는 메뉴 전용 CSS·토큰만으로 되는 것(루트 `index.html`, 시작·레벨·프로필·명예의 전당 스타일). 파일 소유권(루트 `index.html`, 두 앱 `style.css`·`index.html`의 메뉴 구간, `edu.css`)과 "두 앱 소스 동일" 시험 영향을 정확히 적는다.

## 대체됨 표시
원 지침의 감사 화면 목록 중 **게임 HUD·결과 오버레이·컷인·교육용 문제 팝업**, 그리고 시안 요구의 "게임 HUD 4화면"은 **대체됨**(위 범위로). 나머지(웹 조사 원칙 정리, 3안, 글꼴 라이선스·서브셋, 에셋 용량 +10%, 저작권·연상 금지, 접근성, 두 버전 동기화, 권장안·열린 질문, 쓰기 범위 규칙)는 그대로 유효하다.
