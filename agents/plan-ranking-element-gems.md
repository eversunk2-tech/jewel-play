## 사용자가 확정한 결정
1. **랭킹은 "별 챔피언" 한 가지만** 도입한다. 점수 랭킹·점수 도전 모드는 **이번 범위 밖**(2차 확장 후보로만 언급).
2. **호스팅: Cloudflare Workers + D1** (Supabase 등 다른 서비스 사용 안 함).
3. **닉네임: 제한된 자유 입력.** 단어 조합 선택 방식이 아니다. 대신 글자 수·허용 문자 제한, 비속어·개인정보 차단을 **클라이언트와 서버 양쪽**에서 검증한다.
4. 닉네임을 정할 때 **본인 아바타를 선택**한다. 아바타 이미지 15종은 이미 `assets/avatars/avatar-01.webp ~ avatar-15.webp`(192×192, 개당 약 9KB)로 준비돼 있다(마법사·기사·고양이 후드·발명가·늑대·유니콘·슬라임 모자·연금술사·고래 후드·숲 요정·해적·우주비행사·곰·토끼·공룡). 서버에는 **아바타 번호(1~15)만** 저장한다.
5. 대상 사용자는 **초등학생~청소년**. 공개 순위표에 노출되는 정보는 닉네임·아바타·별 수·순위뿐이다. 이름·학교·학년반 등 개인정보는 받지 않는다.

## 해야 할 일 (§19에 포함)
### 1. 랭킹 규칙
- 순위 정렬: **총 별 수 내림차순 → (동점) 클리어한 스테이지의 남은 시간(초) 합계 내림차순 → 그래도 같으면 먼저 달성한 사람(갱신 시각 오름차순)**. 이 규칙이 동점 폭발을 막는지 설명하고, 남은 시간 합계의 정의(레벨별 **최고 기록**의 남은 시간 합? 별이 갱신될 때만 갱신?)와 클라이언트가 보낼 값을 **현재 저장 구조(`stages`)에서 얻을 수 있는지** 확인한다. 얻을 수 없으면 필요한 저장 필드 추가안을 제시(마이그레이션 포함, 기존 데이터 유지).
- 순위표 종류: **전체(통합)** 탭과 **난이도별(초보/중수/고수)** 탭. 통합 점수 정의(단순 합 vs 난이도 가중)를 **장단점과 함께 결정**하라(권장안 하나 + 이유).
- 표시: 상위 50명, 내 순위(상위 50 밖이어도 표시), 1~3위 메달 표시, 새로고침, 마지막 갱신 시각.

### 2. 프로필(닉네임·아바타)
- 최초 실행 시 **프로필 만들기 화면**: 아바타 15종 격자 선택 + 닉네임 입력. 건너뛰기/나중에 설정 허용 여부(건너뛰면 랭킹 미참여)와 변경 규칙(닉네임·아바타 변경 허용, 남용 방지를 위한 제한 예: 하루 N회)을 정한다.
- **닉네임 검증 규칙(제한된 자유 입력)**: 길이(예: 2~8자), 허용 문자(한글 완성형·영문·숫자 등 — 이모지·특수문자·공백 정책), 연속 반복·숫자 과다 제한, **비속어 필터**(한국어 특성 고려: 자모 분리·초성·숫자/특수문자 치환·띄어쓰기 우회, 영어 욕설 포함 — 정규화 방식과 금칙어 목록 관리·갱신 방법), **개인정보 패턴 차단**(전화번호·이메일·URL·"○학년○반"·학교명 패턴 등), 사칭 방지(관리자·운영자·공식 등), 중복 닉네임 정책(허용하되 **구분용 4자리 태그** 부여 vs 유일성 강제 — 권장안과 이유). 학생 대상이므로 **보수적으로** 설계하고 오탐 시 학생이 이해할 수 있는 안내 문구(왜 안 되는지 부드럽게)를 정한다.
- 클라이언트 검증은 UX용, **서버 검증이 최종**(서버는 클라이언트 값을 믿지 않는다).
- 안내 문구: "실명·학교·학년반·연락처를 쓰지 마세요" 등 개인정보 보호 안내와 순위표 공개 범위 고지(화면 문구 초안 포함).

### 3. 서버(Cloudflare Workers + D1) 설계
- **API**: 최소 엔드포인트와 JSON 스키마(예: `POST /api/profile`/`POST /api/submit`(또는 통합), `GET /api/leaderboard?board=all|easy|normal|hard&limit=50&me=<playerId>`), 오류 코드, **버전 필드**.
- **D1 스키마(SQL)**: 테이블/인덱스(순위 조회 성능), 저장 항목은 **닉네임·아바타 번호·난이도별 별 수·최고 클리어 레벨·남은 시간 합계·갱신 시각·익명 playerId**로 최소화. 확장(2차: 점수 랭킹)을 위한 `board` 구분 컬럼 여부를 결정하고 이유를 적는다. 이름·IP 원문·학교 정보는 저장하지 않는다.
- **playerId**: 클라이언트가 만든 무작위 ID(UUID)를 `localStorage`에 저장. 이 ID가 곧 "소유권"이므로 노출/탈취 위험과 한계를 설명하고, 순위표 응답에 playerId를 **노출하지 않는** 설계(공개용 해시/순번 사용)를 제시.
- **서버측 검증(조작 방어)**: 난이도별 별 배열(레벨당 0~3), "레벨 N 별 > 0이면 레벨 1~N-1도 클리어" 연쇄 해금 일관성, 남은 시간 상한(난이도별 시작 시간 이하, 별 등급과 일치: 3★는 ≥50% 등), 합계 상한(난이도 30★), **단조 증가만 허용**(별/시간 합이 줄어드는 제출 거부 또는 무시), 제출 빈도 제한(playerId·IP 단위 — **IP 원문은 저장하지 않고** 해시나 Cloudflare 기능 사용), 요청 크기 제한. 완전한 조작 방지는 불가능함을 솔직히 명시하고 위험 허용 수준을 정리.
- **CORS**: 허용 오리진을 `https://eversunk2-tech.github.io`(+ 로컬 시험용 localhost)로 제한. 그 외 도메인(Vercel 등 추후) 추가 방법.
- **운영/관리**: 교사용 **항목 숨김·삭제**(부적절 닉네임 신고 대응) 수단 — 관리자 비밀키(Worker Secret)로 보호되는 최소 관리 엔드포인트 또는 `wrangler d1 execute`/대시보드 SQL 콘솔 사용 절차. **비밀키·토큰은 저장소에 절대 커밋하지 않는다**(그 방법을 명시).
- **용량·무료 한도 계산**: Workers 무료(하루 10만 요청), D1 무료(하루 읽기 500만·쓰기 10만 행, 저장 5GB 등 — 최신 문서로 재확인)에 대해 "학생 500명, 1인 하루 제출 N회, 순위표 조회 M회" 가정 시 사용량 표와 안전 마진. 순위표 **캐시(예: 30~60초)** 로 읽기 줄이는 방법. D1 무료 한도 초과 시 동작(쿼리 실패) 대비 클라이언트 동작.
- **로컬 시험**: Worker·D1을 로컬에서 시험하는 방법(`wrangler dev --local` 등)과, 계정 없이 시험 가능한 **목(mock) 서버**(Node 또는 정적) 제공 여부.

### 4. 클라이언트 동작
- **서버가 없거나 실패해도 게임은 완전히 동작**해야 한다(오프라인 폴백): 제출 실패 시 로컬 대기열에 보관 후 재시도, 순위표 화면은 오류 안내.
- 제출 시점: 스테이지 클리어 직후(별이 갱신될 때만), 프로필 변경 시. 중복·연타 방지, 컷인·결과 화면 흐름과 충돌 없게.
- API 주소 설정 위치(`CONFIG`에 한 줄), 주소가 비어 있으면 랭킹 기능 숨김(배포 전 안전).
- 시작 화면에 **내 프로필(아바타+닉네임)** 표시/수정 진입점, **명예의 전당** 버튼 추가 위치와 레이아웃(현재 "스카이 캔디" 스타일, 360~1280 반응형, 가로 모드) 설계.
- 접근성·성능(아바타 이미지 지연 로딩, 순위표 50행 렌더링).

### 6. 배포 안내서(사용자는 교사이며 Cloudflare 계정을 직접 만든다)
초보자도 따라 할 수 있는 **단계별 가이드**를 §19에 포함: (a) Cloudflare 가입, (b) D1 데이터베이스 생성, (c) 스키마 적용, (d) Worker 배포 — **대시보드(웹 화면) 방식**과 **wrangler CLI 방식** 둘 다(대시보드 방식은 코드 붙여넣기 기준), (e) 관리자 비밀키 설정, (f) 허용 오리진(CORS) 설정, (g) 게임 `CONFIG`에 API 주소 입력, (h) 동작 확인 체크리스트, (i) 문제 해결(자주 나는 오류). **로그인·결제·비밀키 입력은 사용자가 직접 한다**는 점을 명시(에이전트는 계정 정보를 다루지 않는다).
