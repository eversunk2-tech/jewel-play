# Build 지침 U-B — 메뉴 화면 개선 V1: 레벨 선택 카드 스킨(U-3) + 폰 세로·낮은 화면 마무리(U-5) (spec §32.5·§32.9·§32.7, 승인 기록 §34)

## 역할
너는 **Build 담당**(Sonnet 서브에이전트)이다. 앞 단계 **U-A**(시작·루트 선택·프로필·명예의 전당·교육용 단원 선택, `agents/build-menu-ua-element-gems.md`)의 결과가 이미 작업 트리에 들어 있다. 이번 단계(U-B)는 **레벨 선택 화면을 같은 V1 문법으로 입히고(U-3)**, **폰 세로·낮은 화면·가로 폰 마무리(U-5)**를 한다. **CSS 중심**이다. **게임 규칙·게임 화면(HUD·보드·보석·게이지·컷인·팝업·결과)·`game.js`가 만드는 DOM의 클래스·구조·서버·저장은 한 글자도 바꾸지 않는다.** 검증은 별도 Review가 하며, **네가 직접 확인한 것만 "확인함"** 으로 쓴다.
먼저 읽는다: `CLAUDE.md`, `docs/STATUS.md` §14, `apps/element-gems/spec.md`의 **§32.5(레벨 선택 재설계, 특히 32.5.1 V1 행·32.5.2 상태 4종·32.5.3 접근성·32.5.4 마크업 계약)·§32.7·§32.8(점검표)·§32.9(U-3·U-5 행과 함정 6개)·§33·§34**, **U-A의 보고와 새 코드**(`git diff`로 두 앱 `style.css` 끝의 `/* 메뉴 V1 (spec §32, U-A) */` 블록·`index.html` 변경·`test/menu.test.js`를 읽고, **U-A가 만든 토큰·클래스·접두어를 그대로 이어 쓴다**). 줄 번호는 참고용이니 제목으로 찾는다. 시안 파일은 없다(재부팅으로 사라짐) — 글로 된 설명과 아래 치수가 정답지다.

## 현재 레벨 선택 마크업 (읽기 전용 사실)
- `index.html` `#screen-stages`: `.stages-card` > `.stages-head`(`#btn-stages-back`·`.stages-title`(`#stages-chip` + "레벨 선택")·`#stages-time`) · `#stages-summary.stages-sub` · `#sp-roster.sp-roster`(M4 "깨운 정령 n/6") · `#stage-grid.stage-grid`(role=group) · `#stage-detail.stage-detail`(`.sd-info`: `.sd-head`(`.sd-title`·`.sd-tag`)·`.sd-goal`·`.sd-hint`·`.sd-time` + `#btn-stage-go.sd-go` [도전!]) · `.stages-hint`.
- 카드는 `game.js`(`renderStages`)가 만든다 — **그대로 둔다**: `button.stage-card` + `.locked/.current/.cleared` + `data-stage` + `data-kind="special|rest"`(스킨용, 글자로 안 나옴), 안에 `.sc-num` · (`.sc-target` 초보 | `.sc-mis` 중수·고수) · (`.sc-stars` | `.sc-lock`) · (`.sc-tag` "특별", 중수·고수 5·10만 `aria-hidden`).
- **쉬어가기(3·6·9)는 화면에 표시하지 않는다**(§34). `data-kind="rest"`에 보이는 꼬리표·글자를 넣지 않는다. 초보 카드에는 미션 요약·태그를 넣지 않는다(§33).
- 시안에 있던 카드 안의 정령 그림(`.sc-sp`)·점수 3등분 점(`.sc-steps`)은 `game.js` 변경이 필요해서 **이번에 만들지 않는다**(M4는 정령을 레벨 선택 위쪽 `#sp-roster` 한 줄과 카드 `aria-label`로만 보인다). 특별 카드는 **금 테두리 + `data-kind="special"` 스킨 + (있으면) "특별" 태그**로 구분한다. 이 차이는 보고에 "spec과 달랐던 점"으로 적는다.

## 만들 것 (U-3: 레벨 선택, `.menu-screen` 접두어 안에서)
1. **카드형 5×2** — V1 치수: 카드 **약 211×205**(1180×820 기준, 화면 폭에 따라 비례해 줄임), 번호 **약 50px**, 카드 면적 합 **40% 이상**(현재 15.5%). 같은 배경 정글(카메라 `50% 78%`, U-A 토큰)이 카드 뒤로 비치되 **카드 자체는 불투명한 젤리 느낌**(위쪽 밝은 하이라이트 + 아래 짙은 립)으로 글자 대비를 지킨다. 반투명 유리 금지(번잡해짐 — spec §32.5.1 약점).
2. **상태 4종은 색 외에 모양으로도**(§32.5.2): ① 완료 = 민트 카드 + 왼쪽 위 ✓ 원(`::before`, 글자 아님 `aria-hidden` 불필요한 장식) + 별 ② 현재 = 금 카드 + 빛 테두리 + 위 "도전!" 꼬리표(`::after`) + 기존 `stagePulse` 맥박만 재사용(새 무한 애니메이션 추가 금지, 감소 모션이면 0) ③ 잠김 = 짙은 라벤더 카드 + 자물쇠(CSS 도형/인라인 SVG `data:` URI는 `mask`·`background`가 아니라 **CSS로 그린 도형**을 권장; 외부 주소 금지) + 낮춘 채도, 글자 `#44407a` 이상 대비 ④ 특별(5·10) = 금 테두리 + 보라 면 + 별도 윤곽(색만으로 구분되지 않게 테두리 굵기·모서리 장식으로).
3. **미션 칩(`.sc-mis`)·점수(`.sc-target`)** 글자: 카드가 커졌으므로 현재(.62rem~.85rem)보다 **크게**(최소 12px, 큰 화면 14px 이상) 읽히게. 고수 복합 미션 요약("3가지 미션" 등)이 넘치지 않게 `min-width: 0`·줄바꿈 규칙 확인.
4. **선택 레벨 설명판(`.stage-detail`)**: 카드 5×2 아래에 넓게(카드 폭과 같은 너비), 왼쪽 큰 레벨 번호 + 종류 태그, 가운데 미션/목표 문장(큰 글자 1.1~1.4rem), 오른쪽 [도전!] **높이 ≥ 56px**(M2 시험이 44px 이상을 검사). 교육용의 "선물상자 문제 N개…" `.sd-hint`/학습 줄이 들어가도 넘치지 않게.
5. **`#sp-roster`(M4 "깨운 정령 n/6")**: 새 레벨 선택 윗줄에 자연스럽게(제목 리본 옆이나 아래, 가운데). 글자·작은 정령 6개 그림·`aria-hidden` 구조는 그대로. 레벨 선택 제목은 U-A의 리본 문법(`ribbon`) 재사용.
6. 레벨 선택 `.stages-card`의 흰 큰 패널(780px)은 **없앤다/투명하게** 하고 카드가 풍경 위에 직접 놓이게 한다(§32.5.1 V1 "연못 장면 위 큰 젤리 카드"). 뒤로 단추·난이도 칩·시간은 모서리 칩(U-A 시작 화면 문법).

## 만들 것 (U-5: 폰 세로·낮은 화면·가로 폰 마무리)
7. **폰 세로 390×844·360×640·320×568**: 시작 화면은 **스크롤 0**(U-A가 목표로 한 것을 확인·보정), 레벨 선택은 카드 2열×5행(또는 3열) 등 **카드 면적·터치 타깃 ≥ 44px**을 지키며 보여 준다. 설명판은 카드 아래(또는 고정 하단)에서 [도전!]이 **항상 화면 안**에 있게. `? 게임 방법` 칩은 폰에서 기본 접힘(첫 방문만 펼침 — U-A 규칙 유지).
8. **가로 폰 844×390·740×360·568×320**: 시작·레벨 선택·프로필·명예의 전당이 **깨지지 않고**(잘림·겹침 0) 핵심 단추가 화면 안. 안 되는 곳은 보고에 목록으로.
9. **낮은 화면**(예 1024×600·1366×768 노트북): 스크롤이 생겨도 핵심 단추([시작]·[도전!])가 첫 화면에 보이는지.
10. U-A에서 남긴 보고의 "미해결"을 이어서 처리(지침 범위 안에서만).

## U-A 완료 후 메인 세션이 확인한 사실과 U-A가 남긴 숙제 (추가 지침, 위 내용과 충돌하면 이쪽이 우선)
- U-A 결과(메인 세션이 직접 실행): 시험 **일반용 269 / 교육용 543(542 통과 + 건너뜀 1) / 서버 65**, 두 앱 `style.css` 바이트 동일, `game.js`·`edu.js`·`ranking*.js`·`server/**`·`assets/**` 변경 0. 새 CSS는 `style.css` 끝 `/* 메뉴 V1 (spec §32, U-A) */` 블록(+317줄)과 `edu.css`의 `[EDU] 메뉴 V1` 블록(**문제 팝업 구간 바로 앞에 삽입**됨 — M3-B·M4-B 끝 앵커 시험 때문), 루트 `index.html` 인라인 CSS 끝. U-A 시험 `test/menu.test.js`(일반용 18·교육용 21)가 있다 — **U-B 시험은 이 파일에 추가**한다. U-A가 쓴 가드: 배경 카메라·햇살·잎은 `:has(.menu-screen:not([hidden]))` 양성 조건으로만 켜고 게임 화면 방어 규칙 두 줄만 `#screen-game`을 쓴다(시험 ①이 이 두 줄만 예외로 단언) — **이 방식을 U-B도 따른다**.
- 레벨 선택 화면 `#screen-stages`는 U-A에서 `menu-screen`·`data-cam="low"`만 달아 **카메라·햇살·잎만** 받았다(모양은 그대로 흰 패널 + 작은 카드). U-B가 이것을 카드형으로 바꾼다.
- **숙제 1(U-5)**: 폰 세로에서 **프로필 만들기/고치기 화면이 변경 전보다 길다**(390×844 +104/+52px, 360×640 +30px 정도; 그림 간격 12px로 키운 탓). 같거나 더 짧아지게 줄인다(그림 간격·리본·여백 조정, 그림 터치 대상 ≥ 44px 유지).
- **숙제 2(U-5)**: 폰 세로 **첫 방문(규칙 펼침)** 시작 화면이 스크롤된다(390×844 일반 178px·교육용 361px, 360×640 231/360px). 접힌 상태는 이미 스크롤 0이다. 펼침 때도 [시작]과 `? 게임 방법` 접기 단추가 첫 화면에 보이게 하거나(규칙 패널을 하단 시트/팝오버로), 첫 방문 기본 펼침을 폰에서는 접힘으로 두는 안 중 **더 나은 쪽을 골라** 보고(둘 다 `localStorage` 키 `eg-howto-seen` 규칙을 유지).
- **숙제 3(U-5)**: 가로 폰 844×390 일반용 시작 화면 세로 넘침 221px(기존 505px보다는 적음), 교육용 29px — 가능한 만큼 더 줄이고 [시작]이 첫 화면에 있게.
- **알림 1**: `[시작]` 단추의 흰 글자는 단추 바탕(노랑~주황) 대비 1.42지만 7px 갈색 외곽선 `#8a3d00`(7.64:1)으로 읽힌다(spec 토큰 그대로, 게임의 칭찬 글자와 같은 레시피) — 바꾸지 말고 Review가 보게 둔다. **알림 2**: 명예의 전당 칩이 시각적으로 오른쪽 위인데 탭 순서는 [난이도] 뒤 — DOM 순서 유지(기능 불변), 보고에만 남는다.

## 승인된 결정·제약 (바꾸지 않는다)
- 시안 방향 V1. **글꼴 변경 없음**(`@font-face` 금지), **새 이미지·음원 0개**(`bg-jungle.webp`·`gems/*.webp` 재사용만), 외부 URL·CDN 0, `backdrop-filter`·`blur(` 0.
- **격리**: 새 CSS는 전부 `.menu-screen`(레벨 선택 화면이 `.menu-screen`이 아니면 `#screen-stages` 접두어로 허용 — 단 `#screen-game`·`.gem`·`.timer`·`.gauge`·`.board` 선택자 금지) 접두어. 새 블록은 `style.css` 맨 끝에 `/* 메뉴 V1 (spec §32, U-B) */` 하나로 붙인다(U-A 블록 뒤). **기존 규칙은 고치지 않는다**(덮어쓰기는 새 블록의 접두어 규칙으로). 두 앱 `style.css`는 **바이트 동일**.
- 마크업은 `index.html`의 레벨 선택 구간에서 **래퍼 추가·클래스 추가** 정도만(두 앱 같게, 교육용은 `[EDU]` 구간 차이만). `game.js`가 채우는 id(`stage-grid`·`sd-*`·`btn-stage-go`·`sp-roster*`·`stages-*`)는 **이름·존재 그대로**. 카드 클래스·`data-*`·`aria-label` 그대로.
- 접근성: 본문 4.5:1·큰 글자 3:1(그림 위 글자는 **실제 렌더 색으로 측정**), 터치 대상 ≥ 44px(주요 버튼 ≥ 56px), 색에만 의존하지 않음, `prefers-reduced-motion`이면 새 애니메이션·전환 0, 무한 애니메이션은 화면당 ≤ 3(기존 `stagePulse` 포함), 키보드 순서·포커스 표시(보이는 링)·`aria-*` 유지.
- 기존 시험의 레벨 카드 검사(`mission.test.js`의 M2 CSS 시험: 글자 11px 이상·[도전!] 44px 이상·대비 4.5:1, `widescreen.test.js`, `edu-ui.test.js` 등)를 **단언 약화 없이** 통과해야 한다. 앵커(맨 끝)는 내용 앵커로 옮기되 보고.
