## 검증 항목
1. **spec §17.9 체크리스트 전체**를 표(항목/결과/근거)로.
2. **프리셋·타이머**: 3난이도 시작/상한 시간(130/155, 120/145, 100/120), 시간 보너스(§17.2), 게이지 최대치와 `aria-label`, `m:ss` 표기(2:10/2:00/1:40, 60→`1:00`, 59→`59`), 10초 이하 경고·`warning` 효과음, 감쇠 코드(`timeDecay`/`elapsed`)가 남아 동작에 영향 없는지.
3. **스테이지 규칙**: 목표 30개 값이 §17.4와 일치, 목표 달성 **즉시 클리어**(연쇄 정산 후), 시간 소진 순간 정산 중 달성 시 클리어/미달 시 실패, **클리어와 실패가 동시에 뜨거나 두 번 처리되지 않는지**(스킬·컷인 중 목표 달성, 일시정지·탭 숨김·리셋 연타와 겹칠 때, 2×2 연쇄로 목표 달성), 별 경계(남은 시간 정확히 30%/50%), 잠금 해제·난이도별 독립·재도전 시 최고 기록만 갱신, 레벨 10 클리어 처리, 컷인 중 판정 보류.
4. **UI**: 시작 화면(난이도 3버튼 + 시작 → 레벨 선택), 레벨 선택 화면(5×2 격자, 잠금/현재/별/목표 표시, 뒤로, 키보드 방향키·Esc), 카운트다운의 레벨·목표 안내, HUD 목표 진행 바(100% 도달 연출), 일시정지/결과 화면(클리어/실패/레벨 10 완료의 문구·버튼), `word-break: keep-all` 적용으로 한글 음절 단위 줄바꿈이 사라졌는지, 360×640 / 390×844 / 768×1024 / 가로 800×360 / 1280×800에서 가로 스크롤·잘림 없음(Build가 확인하지 못한 390×844·768×1024 포함), 레벨 카드의 작은 글씨(약 10px) 가독성.
5. **저장**: 옛 형식(`best` 등), 손상 JSON, 타입·범위 오류, 일부 난이도만 손상, 저장소 예외에서 에러 없이 기본값, 새로고침 후 진행도·별 유지, `bestByLevel`/`best` 값 보존.
6. **회귀**: 2×2 규칙(단독/3×3/겹침/초기 보드·재섞기 불변식 Node 재검증), 난이도별 스킬 수치·힌트·초보 자동 힌트, 스킬 6종 컷인→효과 1회, BGM·효과음 연결(클리어=`newbest`, 실패=`timeup`), 콘솔 에러·경고 0건, 에셋 404 없음, DOM/타이머 누수 없음, **귀여운 보석 이미지가 실제로 표시되는지**(프로젝트 폴더 서버 기준).
7. **밸런스·난이도 곡선 재검증(제안만)**: Plan(spec §17.4)은 중수 클리어율 L1 100 / L5 71 / L10 9%라고 했으나 Build의 시뮬레이션은 L1 99 / L5 41 / L10 2%로 나왔다(스킬 횟수 약 20% 낮음). `game.js` 순수 함수로 **독립 시뮬레이션**(난이도·레벨별 300판 이상, 수당 생각시간 모델 3종: 1.3초·1.6초·1.9초 + 숙련 1.0초, 컷인 중 시계 정지 반영, 가정 명시)을 돌려 **레벨별 클리어율 표**를 만들고 다음을 판단한다: ① 초등학생 대상 초보 난이도의 후반 레벨이 "열심히 하면 깰 수 있는" 수준인가(예: 중간 모델 1.9초에서 초보 L10 클리어율), ② 같은 레벨에서 초보 > 중수 > 고수 순서가 유지되는가, ③ 곡선이 단조 감소하는가. 목표 점수를 어떻게 조정하면 좋은지 **수치 제안**을 표로 적는다(적용하지 말 것).
8. 사용자에게 보이는 문구(레벨 선택·결과·안내)의 오탈자·어색한 표현.
