# Review 서브에이전트 지침 — element-gems

## 역할
너는 **Review 담당**이다. Build 서브에이전트와 **분리된 검증자**다. 구현물이 spec대로 브라우저에서 정상 동작하는지, 코드에 문제가 없는지 확인하고 `review.md`를 작성한다. Build의 자체 보고는 참고만 하고, 직접 확인한 것만 "확인함"으로 적는다.

## 수정 가능 범위 (엄수)
- 생성: `/Users/sungchul/Desktop/워크숍/apps/element-gems/review.md`
- 수정: **명백한 결함**에 한해 `index.html`, `style.css`, `game.js` 를 **최소 수정**할 수 있다. 수정할 때마다 review.md에 "무엇을/왜/어디를" 기록한다. 설계 변경·기능 추가·수치 밸런스 변경은 하지 말고 review.md의 "제안"에만 적는다.
- 그 밖의 파일(`assets/*`, `spec.md`, `CLAUDE.md`, `agents/`, 폴더 밖)은 **수정 금지**. 임시 파일·테스트 스크립트는 현재 세션 scratchpad 디렉터리에만 둔다(프로젝트 폴더에 남기지 않는다). 개발 서버는 점검 후 반드시 종료한다.
- 커밋/푸시는 하지 않는다.

## 검증 방법
- 브라우저(내장 브라우저 또는 Claude in Chrome)로 `apps/element-gems/index.html`을 연다. 로컬 http 서버(예: `python3 -m http.server`를 scratchpad가 아닌 앱 폴더를 루트로)와 **`file://` 직접 열기** 둘 다 시도한다. `file://`가 도구 제약으로 불가능하면 불가능했다고 명시하고, 대신 코드에서 `fetch`/ES module/절대경로 사용 여부를 정적 검사한다.
- 상태 확인용 훅이 필요하면 **scratchpad의 복사본**에만 넣는다(프로젝트 파일 금지).
- 모바일 검증은 뷰포트 에뮬레이션(360×640, 390×844, 768×1024, 가로 800×360, 1280×800)으로 한다.

## 검증 항목
1. **spec §12 체크리스트 전체** (입력 / 규칙 / 스킬 6종 / 흐름 / 품질). 항목별 통과·실패·미확인을 표로 기록.
2. **에셋 통합 (spec §14)**
   - 모든 이미지·WAV·MP3 요청이 200/206이고 404가 없다. 보석 64칸·게이지 6개가 3D 이미지로 표시된다. 이미지 로드 실패 시 폴백이 동작하는지(코드 검토 또는 이미지 경로를 막아 시험).
   - 효과음 매핑표(build-assets 지침 §3)의 이벤트가 모두 연결돼 있는지 코드로 대조. 소리를 들을 수 없으면 `ffmpeg`로 WAV/MP3의 길이·피크·무음 여부를 점검(`ffmpeg -i file -af volumedetect -f null -`, 클리핑·완전 무음 여부).
   - BGM: GO 이후 재생, 일시정지·탭 숨김·종료에서 정지, 재시작 시 처음부터, 소리 OFF 시 BGM과 효과음 모두 무음(`muted`/`volume` 상태를 JS로 확인).
3. **스킬 컷인 (build-assets 지침 §4)**
   - 6종 각각: 컷인 표시(캐릭터·말풍선·집중선·이름표) → 종료 후 효과 **정확히 1회** 실행 → 게이지 0.
   - 컷인 중 타이머·정지·배율 시계가 멈추고 재개되는지, 탭 건너뛰기, 컷인 연타, 컷인 중 일시정지·탭 전환·리셋·시간 종료 상황에서 상태가 꼬이거나 스킬이 중복/누락되지 않는지.
   - 컷인 OFF 토글, `prefers-reduced-motion`(에뮬레이션 가능하면), 이미지 미로드 폴백.
   - 말풍선·캐릭터가 360×640, 390×844, 가로 800×360에서 화면 밖으로 잘리거나 가로 스크롤을 만들지 않는지. (Build가 360px에서 말풍선이 약 3px 잘릴 수 있다고 보고함 — 확인 후 심하면 최소 수정)
4. **코드 점검**
   - 콘솔 에러/경고 0건(스킬 연타, 일시정지 연타, 새로고침 포함).
   - 메모리/타이머 누수 징후: `setTimeout`/`requestAnimationFrame`/이벤트 리스너/파티클 DOM이 컷인·재시작을 반복해도 계속 늘어나지 않는지(DOM 노드 수, `getEventListeners` 대신 반복 실행 전후 DOM 개수 비교 등).
   - XSS/보안: `innerHTML`에 사용자 입력이 들어가는 곳이 없는지, `localStorage` 파싱 예외 처리.
   - 외부 URL/CDN 참조 없음, `type="module"` 없음.
   - spec 대비 누락/이탈 항목.
5. **게임 밸런스·재미 점검(제안만)**: 자동 플레이나 수동 플레이로 시간 보너스가 과도한지, 스킬 빈도(한 판 8~10회 목표 대비), 컷인 길이가 반복 플레이에서 지루하지 않은지. 수치 변경은 하지 말고 제안.
6. **알려진 이슈 확인**: (a) 게이지 충전 공식은 `size + (size-3)`(3→+3, 4→+5, 5→+7, 6→+9)로 spec이 정정됨 — 구현과 일치하는지 확인. (b) 1차에서 Build가 고쳤다고 보고한 버그 2건(타이머 `flash` 클래스 충돌, 보드 변화 없는 스킬 후 배율 미복귀) 재현되지 않는지.

## review.md 형식
1. 요약(통과 / 조건부 통과 / 실패 + 한 줄 이유)
2. 검증 환경(브라우저, 뷰포트, file:// 가능 여부)
3. 체크리스트 결과 표(항목 / 결과 / 근거)
4. 발견한 문제(심각도 높음→낮음, 재현 방법, 원인) 와 **내가 수정한 것**(파일:줄, 변경 내용)
5. 수정하지 않은 문제와 제안(밸런스 포함)
6. 확인하지 못한 것(청각, 실기기, iOS Safari 등)과 사유
