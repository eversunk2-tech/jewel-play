## 역할
너는 **Plan 담당**이다. 구현하지 않는다. 아래 사용자 요청과 메인 세션이 이미 확인한 사실을 바탕으로 `apps/element-gems/spec.md` **끝에 새 `## 22.`를 추가**한다(기존 §1~§21은 한 글자도 고치지 않는다). 사용자는 아직 승인하지 않았고, 시안 선택(곡·효과음)도 아직 하지 않았다. 그래서 **선택에 따라 달라지는 부분은 "열린 질문"으로 두고 권장안을 함께 쓴다.**

## 사용자 요청 (2026-11-08)
1. 시작(메인) 화면 배경음악을 Gemini '음악 만들기'로 새로 만들어 넣는다. 게임에 기대감을 주는 곡. (현재 플레이 BGM은 "생동감 있고 즐거운 멜로디로 잘 만들었다"는 평가)
2. 메뉴 버튼을 누를 때 효과음을 지금보다 조금 더 귀여운 느낌으로 바꾼다(시안 제안).
3. 플레이 배경음악을 여러 곡으로 늘리고 **한 판마다 랜덤**으로 나오게 한다(지금은 1곡).
4. 질문: 1~10단계 통과 점수가 너무 높은 것 아닌가 → **클리어 난이도 재판정**과 조정안.

- **22.1 개요·결정 요약 표**(항목 / 결정(초안) / 근거).
- **22.2 클리어 난이도 재판정**: 위 사실을 표로(현재 vs 조정안 B vs P1 vs 고수 ×1.06/×1.14, 모델별 클리어율·시도 수), 판정 문장, 한계(모델 근사·사람 ±20~25%·청각 무관), 적용 위치, 교육용 영향, 사람 플레이 뒤 재조정 절차(사용자 실제 막힌 지점 활용).
- **22.3 배경음악 구조**: (a) 시작 화면·단계 선택 화면 BGM — 재생 시점(브라우저 자동재생 정책: 첫 터치/클릭 뒤 시작, `audio.init()`와의 관계), 소리 토글·저장 키와 연동, 화면 전환별 동작(시작→단계 선택→플레이→결과→다시 시작 화면)과 **곡 교체 시 짧은 페이드**(해도 되는지 근거), 탭 숨김·일시정지·컷인 덕킹과의 상호작용; (b) 플레이 BGM 재생목록 — 판 시작 때 무작위로 1곡(직전 판과 같은 곡 연속 회피, 곡 수가 1이면 그대로), 곡이 판 중간에 끝나면 같은 규칙으로 다음 곡, **지연 로드**(그 판에 쓸 곡만 `src` 설정, 미리 로딩 시도는 다음 곡 1개까지 허용 여부), 로드 실패 시 폴백(`bgm.mp3` 또는 무음), 재생목록·경로·음량은 `CONFIG`의 한 곳, `CONFIG.assets.bgm` 호환 처리; (c) 새 곡의 끝 페이드 문제와 해결 방식 비교(재생목록 vs 겹쳐 잇기 vs 파일 끝 자르기)와 권장안.
- **22.4 버튼 효과음 교체**: 어떤 파일을 바꾸는지(`click.wav` 교체인지 새 이름인지), 적용 범위(모든 `.btn` 공통인지 [시작]·[계속하기] 같은 주요 버튼만 다른 소리인지), 음량 유지(`CONFIG.audio.sfx` 0.8, 평균 −11~−15dB), 길이 상한(0.25초), 청각 확인 불가와 사용자 선택 방식.
