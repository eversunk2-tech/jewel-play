# Plan 변경 지침 — 3분 → **2분**, 그리고 **난이도별 레벨 1~10 스테이지 시스템** 추가

> 이 문서는 `agents/plan-time180-element-gems.md`를 **부분적으로 대체**한다. 충돌하면 이 문서가 우선이다. 수정 범위·금지 사항(spec.md 끝 §17 추가/갱신만, 코드·assets·review.md·CLAUDE.md·agents 읽기 전용, 커밋/푸시 금지, 시뮬레이션 스크립트는 scratchpad에만)은 그대로다.

## 사용자의 변경 요청 (원문 요지)
1. "3분 말고 **2분**으로 해줘." → 기본(중수) 한 판 제한 시간 **120초**.
2. "초보/중수/고수를 선택하고 나면, **각 난이도별로 level 1부터 level 10까지 스테이지를 클리어해 나가는 것**으로 바꿀게. **스테이지별 클리어 점수는 네가 직접 판단해서 설정해줘.**"

## 이미 §17을 쓰기 시작했다면
§17은 당신이 쓰는 섹션이므로 **3분 기준 내용을 2분 기준으로 고쳐 쓰고** 아래 스테이지 내용을 같은 섹션에 통합한다. 섹션 제목은 `## 17. 플레이 시간 2분 + 스테이지(레벨 1~10) 시스템` 으로 바꿔도 된다. 다른 섹션(§1~§16)은 수정하지 않는다.

## A. 시간 (2분)
- 시작 시간: 중수 **120초**. 난이도 비례 유지 기본안: 초보 약 130초 / 고수 약 100초. 더 좋은 안은 근거와 함께 제안.
- 상한(max), 시간 보너스, **보너스 감쇠 시점**(현재 "경과 90초 이후 ×0.5")을 2분 판에 맞게 재설정. 스테이지 모드에서는 **목표 점수를 달성하면 즉시 클리어**되므로 "숙련자가 판을 무한정 늘리는" 문제는 줄어든다 — 이를 반영해 보너스를 단순화할 수 있으면 제안.
- UI: 타이머 표시 `m:ss`(60초 초과 시 예 2:00), 시작 화면 규칙 문구("제한 시간 N초" → 스테이지/목표 점수 안내로 대체) 등.

## B. 스테이지 시스템 (신규, 핵심)
**구조**: 난이도 선택(초보/중수/고수) → **레벨 선택 화면(1~10)** → 스테이지 플레이. 총 30 스테이지.
**클리어 조건(기본안)**: 제한 시간 안에 **목표 점수**에 도달하면 즉시 클리어(진행 중인 연쇄가 정산된 뒤 "STAGE CLEAR!"). 시간이 0이 될 때까지 도달하지 못하면 실패("TIME UP", 같은 레벨 재도전). 다른 방식(시간 종료 시점에 점수로 판정 등)이 더 낫다고 판단하면 근거와 함께 제안.
**진행/잠금**: 각 난이도마다 레벨은 순서대로 잠금 해제(레벨 N 클리어 → N+1 해제). 이미 클리어한 레벨은 재도전 가능. 난이도 자체는 처음부터 모두 선택 가능. 난이도별 진행도는 독립.
**별 등급(선택, 초등학생 대상이라 권장)**: 목표 점수 달성 ★1, 목표의 약 130% ★★, 약 160% ★★★ (또는 남은 시간 기준 등 더 단순한 안). 넣을지 여부와 기준을 제안하고 열린 질문으로 남긴다.
**HUD**: 현재 `레벨 N`, 목표 점수와 **목표 진행 바**(현재 점수/목표) 표시. 일시정지·결과 화면에 난이도·레벨 표시.
**결과 화면**: 클리어(점수, 별, `다음 레벨` / `다시 하기` / `레벨 선택`), 실패(`다시 도전` / `레벨 선택`). 레벨 10 클리어 시 난이도 완료 축하 문구.
**저장(`element-gems:v1`)**: 난이도별 진행도(해제된 최고 레벨), 레벨별 최고 점수/별. 기존 `bestByLevel`(난이도별 최고 점수) 및 `level`(선택 난이도) 키와의 **충돌 없이** 확장하고 마이그레이션 규칙(옛 데이터는 그대로 열리되 진행도는 레벨 1부터)을 명시. 키 이름 충돌 주의: 기존 `level`은 "난이도"를 뜻하므로 새 키는 `stage`/`progress` 등으로 구분한다.
**시작 화면 흐름 영향**: 시작 화면의 난이도 3버튼과 `시작` 버튼의 역할(→ 레벨 선택 화면으로 이동), 뒤로 가기, 모바일 레이아웃.

## C. 스테이지별 목표 점수 — **이번 Plan에서 네가(에이전트가) 시뮬레이션으로 직접 설정**
- 난이도별 점수 배율(초보 ×0.8 / 중수 ×1.0 / 고수 ×1.3)이 이미 있으므로 **최종 표시 점수 기준**으로 목표를 정한다.
- **방법**: 난이도별로 캐주얼 모델(수당 생각시간 약 1.6초)과 숙련 모델(약 1.0초)을 120초 판(난이도별 시간)으로 **각 300판 이상** 시뮬레이션해 점수 분포(평균/중앙값/p10/p50/p90)를 얻고, 아래 설계 원칙으로 레벨 1~10의 목표를 배치한다. 목표 점수는 **읽기 쉬운 값**(예: 100 또는 500 단위 반올림)으로.
- **설계 원칙**:
  - 레벨 1 = 거의 누구나(캐주얼 모델 클리어율 약 90% 이상), **레벨 10 = 해당 난이도에서 상당한 도전**(캐주얼 모델 클리어율 약 10% 내외, 숙련 모델은 높은 확률로 가능).
  - 레벨 진행에 따라 **클리어율이 대체로 단조 감소**하도록 곡선을 설계(완만한 상승; 후반 가파름 허용). 초등학생이 중간에 막히지 않도록 초보 난이도의 후반 레벨도 "열심히 하면 가능"한 수준.
  - 난이도 간 균형: 같은 레벨 번호에서 초보 < 중수 < 고수 체감 난이도 순서(점수 배율 반영 후 기준).
  - 레벨별로 점수 외 난이도 상승 요소를 추가할지(예: 상위 레벨에서 시간 보너스 약간 감소) 필요성을 시뮬레이션으로 판단하고, **필요 없으면 목표 점수만**으로 구성한다(단순함 우선). 추가한다면 한 가지 축으로 최소화하고 이유를 적는다.
- **결과 표**(필수): 난이도 × 레벨 1~10 목표 점수 표 + 각 칸의 캐주얼/숙련 모델 예상 클리어율(%) + 난이도별 점수 분포 요약. 가정과 한계(근사 시뮬레이션, 실제 사람 플레이로 재조정 필요)를 명시.

## D. 스킬·게이지 재보정 (2분 판 기준)
판이 60초 → 120초로 길어지므로 같은 게이지 값이면 스킬이 약 2배 나온다. 컷인(약 1.3초, 그동안 타이머 정지)이 반복돼도 지루하지 않은 범위로 **스킬 사용 횟수 목표를 새로 제안**(권장 출발점: 초보 18~24 / 중수 14~18 / 고수 10~14회/판)하고 이에 맞춰 난이도별 게이지 최대치를 재산정한다. 단 원래 요청("게이지가 다 차는 데 성공 횟수가 너무 많이 필요하다")의 취지에 따라 **1회 스킬당 필요한 매치 그룹 수가 현재(초보 약 5 / 중수 약 6 / 고수 약 7)보다 20% 넘게 늘지 않도록** 하고, 트레이드오프를 표로 설명한다. 스킬 점수(칸당 10점)가 목표 점수 달성에 미치는 영향도 시뮬레이션에 반영한다.

## E. §17에 포함할 항목 (갱신)
1. 개요·결정 요약
2. 난이도별 새 시간 프리셋 표(시작/상한/보너스/감쇠 시점)와 게이지 최대치(기존 값 대비)
3. **스테이지 시스템 규칙**(클리어/실패, 잠금, 별, 흐름도)과 **난이도×레벨 목표 점수 표 + 예상 클리어율**
4. 시뮬레이션 방법·가정·결과(기준선 재현 포함)·한계
5. UI/문구 변경 목록(타이머 m:ss, 레벨 선택 화면, HUD 목표 진행 바, 결과 화면 버튼, 시작 화면 문구)과 저장 구조·마이그레이션
6. 구현 영향 범위와 단계 분해(Build용), 검증 체크리스트(Review용: 30개 스테이지 값·잠금 해제·저장·실패/클리어 흐름·레벨 선택 UI·모바일·마이그레이션·타이머 표기)
7. 열린 질문(최대 5개: 별 등급, 즉시 클리어 vs 종료 시 판정, 목표 점수 곡선, 난이도별 시간 등)

## 완료 보고 (짧게)
§17 위치, **난이도 × 레벨 1~10 목표 점수 표(예상 클리어율 포함)**, 난이도별 새 시간·게이지 핵심 수치, 시뮬레이션 요약(기준선 재현 여부, 목표 달성 여부), 열린 질문.
