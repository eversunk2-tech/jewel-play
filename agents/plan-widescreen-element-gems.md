# Plan 서브에이전트 지침 — 태블릿·PC(와이드 화면) 레이아웃 (spec §20)

## 역할
**계획만** 작성한다(코드·에셋 수정 금지). 결과는 `apps/element-gems/spec.md`의 **새 `## 20.`** 로 **추가**하고(기존 §는 고치지 않는다), 시안(스크린샷)을 만든다. 구현은 사용자 승인 뒤 Build가 한다.

## 사용자 요청과 결정
"지금 게임 화면은 휴대폰 세로 보기에 최적이다. 태블릿이나 PC에서는 양옆이 너무 비어 보인다." 사용자가 **1번안(와이드 레이아웃)** 을 승인했다(2026-11-07):
- 가로로 넓은 화면(대략 폭 900px 이상의 가로형: 태블릿 가로·노트북·PC·전자칠판)에서는 **왼쪽에 큰 보드, 오른쪽에 패널**(타이머·점수·목표 바·원소 게이지·버튼)을 둔다.
- 시작·난이도/레벨 선택·명예의 전당·프로필·결과·일시정지 화면도 넓은 화면에서 카드 폭을 넓히고 필요하면 2열로 배치해 **양옆 빈 공간을 의미 있게 채운다**.
- 세로 태블릿(예: 768×1024, 820×1180)은 지금 구조를 유지하되 보드 상한(520px)을 키운다(약 680px 안).
- **휴대폰(세로·기존 가로 모드)은 현재와 동일하게 유지**한다(회귀 금지). 사용 환경 가정: 초등학교의 크롬북(1366×768, 1280×720)·전자칠판·교사용 PC·태블릿.

## 계획에 포함할 것 (spec §20)
1. **현황 분석(측정)**: 1366×768, 1280×720, 1280×800, 1920×1080, 1024×768, 768×1024, 820×1180에서 현재 보드 크기·점유율·빈 공간 비율을 **측정값**으로 표로 정리(스크린샷 근거). 보드가 짧은 노트북에서 휴대폰보다 작아지는 문제를 수치로 보인다.
2. **브레이크포인트·분기 조건**: 와이드 레이아웃을 켜는 조건(폭·높이·방향·종횡비)을 정확히 정의하고, 기존 휴대폰 가로 모드(max-height 500px)와 **겹치거나 충돌하지 않게** 정리한다. 터치 태블릿 가로(1024×768, 1180×820)와 PC 창 크기 조절(창이 좁아지면 기존 레이아웃으로 자연스럽게 복귀)을 다룬다.
3. **게임 화면 레이아웃**: 보드를 세로 높이에 맞춰 최대한 크게(상한 포함), 오른쪽 패널의 구성·폭·순서(타이머·점수·목표 바·게이지·버튼·시간 막대 등), 보드와 패널의 정렬, 중앙 배치 방식. 계산식을 CSS 변수로 제시한다(`--board`, `--ui-h` 대체/추가 변수). 보드 크기가 바뀔 때 `game.js`의 크기 의존 로직(셀 크기, 이펙트·컷인 좌표, 입력 좌표)이 **CSS 변수를 그대로 따라오는지** 확인하고, 바꿔야 할 JS가 있으면 최소 범위로 명시한다.
4. **기타 화면**: 시작 화면(로고+시작/난이도+순위 미리보기 등 2열 가능성), 난이도·레벨 선택(레벨 격자 열 수), 명예의 전당(목록+내 순위 사이드), 프로필 만들기(아바타 격자 열 수), 결과·일시정지·프로필 안내 팝업, 스킬 컷인(비율·크기), 툴팁/안내문. 각각 **넓은 화면 배치안**과 **하지 않을 것**(과한 변경 제외)을 구분한다.
5. **세로 태블릿**: 보드 상한 조정안(680px 근처), UI 높이 재계산, 아바타·카드 크기.
6. **마우스·키보드**: hover/focus 상태 보강안, 포인터 정밀도(`pointer: fine`)에 따른 작은 보정만 허용(터치 타깃 44px 규칙은 터치 환경에서 유지). 키보드 단축키는 **범위 밖**으로 기록(필요하면 제안만).
7. **배경·장식**: 와이드 화면에서 정글 배경과 파스텔 틴트가 어색하지 않은지(늘어남·잘림), 양옆 장식 추가 여부(추가 에셋 없이 CSS만으로).
8. **성능·접근성**: 큰 보드에서 프레임·필터 비용, `prefers-reduced-motion`, 대비 유지, 줌 200%에서 깨지지 않기.
9. **시안(필수)**: scratchpad(`/private/tmp/claude-501/-Users-sungchul-Desktop-play2-jewel-play/a531f417-6e12-4899-8faf-38c202023dbb/scratchpad/wide-plan/`)에 **현재(before) 스크린샷과 제안(after) 목업 스크린샷**을 1366×768·1920×1080·1024×768·820×1180(세로)·1280×720에서 게임 화면·시작 화면·명예의 전당에 대해 만든다. 목업은 **현재 CSS를 복사한 시험용 사본(scratchpad)** 에서 새 규칙을 덧붙여 실제 렌더링으로 만든다(프로젝트 파일 수정 금지). 시험 서버는 로컬(`localhost`)만, 끝나면 종료.
10. **구현 영향 범위·단계 분해(Build용)**: 수정 파일·함수·CSS 블록, 단계(① 변수·게임 화면 ② 기타 화면 ③ 세로 태블릿·미세 조정), 단계별 수용 기준.
11. **검증 체크리스트(Review용)**: 휴대폰 회귀(360×640·390×844·가로 844×390·800×360은 **현재와 픽셀 수준으로 동일**한지 비교 방법 포함), 와이드 뷰포트 목록, 경계 해상도(899/900, 1023/1024 등), 입력(터치·마우스), 컷인·이펙트 위치, 콘솔 오류 0, 가로 스크롤 0.
12. **열린 질문(최대 5)**: 사용자 판단이 필요한 것만, **권장안을 먼저**.
13. **위험과 한계**: 확인하지 못한 것(실제 전자칠판·크롬북 기기, 터치 정밀도), 회귀 위험, 에셋 해상도 한계.

## 작업 규칙 (CLAUDE.md)
- 수정 가능: `apps/element-gems/spec.md`(끝에 `## 20.` **추가만**). 그 밖의 프로젝트 파일은 읽기 전용. 임시 파일·사본·스크립트는 scratchpad에만.
- 브라우저 시험은 **새 탭 + `tabId` 명시 + 로컬 서버(`localhost`)만**, `localStorage` 접근 전 `location.origin` 확인, 배포 주소(`github.io`)와 기존 탭은 건드리지 않는다. 시험 후 뷰포트 에뮬레이션은 `desktop` 프리셋으로 되돌리고 탭·서버를 정리한다.
- 현재 다른 에이전트가 `nick-words.js`·`nickname.js`·`server/`를 수정 중이다(읽기만, 무관).
- 커밋·푸시 금지. 승인 전 구현 금지.
