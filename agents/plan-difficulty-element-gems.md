2. 보석 **스킬 게이지(경험치)를 다 모으려면 성공(매치) 횟수가 너무 많이 필요**하다. **전체적으로 조금 낮추고**, **난이도에 따라 또 조정**한다.

## 먼저 읽을 것

## 현재 값(출발점)
- 게이지 최대치: 불 18 / 물 22 / 풀 18 / 번개 20 / 어둠 22 / 빛 24, 충전 `gain = size + (size-3)` (3매치 +3, 4매치 +5 …).
- 시간: 시작 60초, 상한 90초, 보너스 3매치 +0.25 / 4매치 +0.5 / 5매치+ +1.0.
- 스킬 수치: 물 정지 5초, 어둠 ×2 8초, 빛 +4초·힌트 8초, 번개 최대 8개 제거, 불 3×3, 풀 십자. 힌트 쿨다운 8초.

## 설계 방향 (이 틀을 지키되 세부 수치는 시뮬레이션으로 보정)
- **전체 하향**: 지금 게이지가 "꽤 많은 성공 횟수"를 요구한다. 중수(기본)가 현재 값보다 **약 30% 낮은** 최대치가 되도록 하고, 초보는 **약 50% 낮게**, 고수는 현재 값보다 **약 15% 낮게**(고수도 "조금 낮춤") 출발점으로 잡는다. 정수로 반올림하고 색별 개성(물·어둠·빛은 상대적으로 큼)은 유지.
- 난이도별로 조정할 후보 축(전부 쓸 필요는 없고, **효과가 큰 것 위주로 3~5개** 고르고 이유를 적는다):
  1. 스킬 게이지 최대치 배율(필수)
  2. 시작 시간 / 상한 / 시간 보너스
  3. **보석 색 종류 수**(예: 초보 5종 = 매치가 쉬움, 중수·고수 6종). 5종이면 어떤 원소를 뺄지, 그 스킬이 사라지는 문제를 어떻게 할지 **명시적으로 결정**하라(권장: 6종 유지가 스킬 6종 전부 경험시키는 핵심이므로 기본은 6종 유지, 초보에 한해 대안으로 제안만).
  4. 힌트: 초보는 일정 시간(예: 6초) 입력 없으면 **자동 힌트**, 쿨다운 짧게 / 고수는 쿨다운 길게·자동 힌트 없음
  5. 스킬 효과 강도(초보는 유리한 쪽: 물 정지 길게, 어둠 배율 지속 길게 등 / 고수는 기본 또는 약간 짧게)
  6. 점수 배율(난이도 보정 점수, 예: 초보 ×0.8 / 중수 ×1.0 / 고수 ×1.3)과 **난이도별 최고 점수 분리 저장**
- 호환성: 난이도 값은 `CONFIG`를 난이도별 프리셋 객체로 감싸 `CONFIG.difficulty[level]`을 읽는 구조를 권장. 기존 `element-gems:v1` 저장 데이터와 충돌하지 않게(마이그레이션 규칙 포함): 예) `best` → `bestByLevel: {easy, normal, hard}`, 기존 `best`는 `normal`로 이관, 선택한 난이도 `level` 저장.

## 시뮬레이션으로 보정할 것 (필수)
`game.js`의 순수 로직을 Node에서 불러 **난이도별로 한 판 시뮬레이션**(각 300판 이상)하여 아래 목표에 수치를 맞춘다. (review.md가 쓴 방식 참고: 수당 생각시간+스왑·낙하 애니메이션 시간을 게임 시계에 반영, 스킬 효과는 근사. 시뮬레이션이 근사임을 명시.)
- **스킬 사용 횟수(한 판)**: 초보 약 12~16회 / 중수 약 8~11회 / 고수 약 5~8회
- **한 판 길이(캐주얼 중앙값 기준)**: 초보 약 90~120초 / 중수 약 70~90초 / 고수 약 50~70초 (종료되지 않는 판이 없어야 함)
- 색별 스킬 사용 편중이 심하지 않은지(어떤 색 스킬이 거의 안 나오면 최대치 재조정)
결과 표(목표 vs 시뮬레이션 평균·중앙값·p10/p90)를 §15에 넣는다. 목표에 못 맞췄다면 이유와 대안을 적는다.

## §15에 반드시 포함할 항목
1. 개요와 난이도 이름(한국어 UI: **초보 / 중수 / 고수**, 내부 키 `easy/normal/hard`)
2. **난이도별 프리셋 표**(게이지 최대치 6색, 충전 규칙 변경 여부, 시작·상한 시간, 시간 보너스, 힌트/쿨다운/자동 힌트, 스킬 효과 수치, 점수 배율, 보석 종류 수)
3. 시뮬레이션 방법·결과 표·한계
4. UI: 시작 화면의 난이도 선택(세 버튼, 기본 선택값, 선택 유지), 난이도별 간단한 설명 문구, 게임 중 현재 난이도 표시, 종료 화면에 난이도 표시, 난이도별 최고 점수 표시
5. 저장 데이터 변경(`element-gems:v1` 키 구조, 마이그레이션)
6. 구현 영향 범위(`CONFIG` 구조 변경 지점, 건드릴 함수/화면)와 단계 분해(Build용)
7. 검증 체크리스트(Review용): 난이도 3종 각각의 시작 시간·게이지 최대치·보너스·힌트 동작, 난이도 전환/재시작 시 상태 초기화, 저장 마이그레이션, 컷인/스킬과의 상호작용 등
8. 열린 질문(사용자 승인 시 결정할 것, 최대 5개)
