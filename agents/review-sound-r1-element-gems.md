# Review 지침 R1 — 소리 변경 검증 (spec §22.3·§22.4·§22.5·§22.8 소리 항목, 일반용·교육용 모두)

## 역할
너는 **Review 담당(R1)** 이다. Build(B1·B2)를 만든 에이전트와 **별개로** 독립적으로 검증한다. 빌드 보고("확인함")를 믿지 말고 **직접 실행해서 확인한 것만 "확인함"** 으로 적는다. 소리를 들을 수 없으므로 **청각은 "확인하지 못함"** 으로 기록한다. 결과는 `apps/element-gems/review.md` **끝에 `## 18. 소리 개선 검증 (spec §22, R1)` 로 이어 붙인다**(기존 내용은 고치지 않는다, `cat >> … <<'EOF'`). **명백한 결함은 최소 수정**하고(수정 위치·이유를 기록), 설계 변경은 제안으로만 남긴다.

## 필독
`CLAUDE.md`, `docs/STATUS.md` §12, `apps/element-gems/spec.md` §22 전체(특히 22.3·22.4·22.5·22.8 소리(R1) 체크리스트), 일반용·교육용 `game.js`의 `audio` 객체·`CONFIG.audio`·`CONFIG.assets`·`pickTrack`·`startStage`·`goHome`·`goStages`·`finishStage`·`toggleSound`·`bindUi`·`visibilitychange`, `test/audio.test.js`(두 앱), `apps/element-gems/review.md` 끝부분(형식 참고).

## 일하는 법
1. **전체 시험**: `node --test apps/element-gems/test/` 와 `node --test apps/element-gems-edu/test/` 를 직접 실행해 개수(통과/실패/건너뜀)를 기록한다(일반용 기존 60 + 신규, 교육용 기존 224(223 통과·1 건너뜀) + 신규).
2. **파일 검증**: 두 앱 `assets/music/*.mp3`·`assets/sfx/click.wav`가 **서로 바이트 동일**(`cmp`)이고 크기가 §22.5.1 표와 일치(menu 1,379,726 / bgm 1,415,043 / play-1 1,431,762 / play-2 1,360,709 / play-3 1,420,059 / click 14,156). `ffprobe`로 64kbps·44.1kHz·스테레오·길이, `ebur128`로 곡 간 LUFS 차 ≤ 0.3, 디코드 float 최대 ≤ 0.97(ffmpeg로 f32le 디코드 후 파이썬 `array`로 계산). 다른 효과음 25종이 바뀌지 않았는지 `git diff --stat`로 `click.wav`만 바뀌었는지 확인.
3. **코드 읽기**: §22.3.3의 불변식(① 소리 내는 BGM 요소 1개 ② 모든 `play()` `.catch(noop)` ③ 곡 교체 전 `musicGen++` ④ 곡 하나면 `loop=true`·둘 이상이면 `false` ⑤ `Audio` 없으면 타이머 없음), 첫 입력 핸들러(`click`·`touchend`·`keydown` 캡처, `pointerdown` 미사용), 지연 로드(목록 전체 미리 설정 없음), 다음 곡 미리 받기 없음, 폴백 순서(실패 곡 제외 재시도 → `CONFIG.assets.bgm` → 무음), 레이스(낡은 페이드 타이머·`play()` 약속·`ended`가 새 상태를 되돌리는지), 소리 꺼짐 상태에서 파일을 받지 않는지, 교육용 `[EDU]` 블록 보존.
4. **브라우저 확인**(두 앱 모두): **로컬 서버(`localhost`) + 새 탭 + 모든 호출에 `tabId` 명시 + `localStorage` 접근 전 `location.origin` 확인, 배포 주소(`github.io`)·실서버(`workers.dev`)·기존 탭 금지.** 페이지 스크립트 전에 `HTMLMediaElement.prototype.play/pause`와 `src` 설정을 가로채 호출 로그를 남기고 네트워크 요청과 함께 §22.8 소리 체크리스트를 **항목별로** 확인한다(첫 입력 전 mp3 요청 0 / 첫 입력 뒤 `menu.mp3` 1개 / 화면 전환에서 곡 재시작 없음 / 판 시작 때 곡 1개 요청 / 10판 반복 직전 곡 연속 없음·네 곡 모두 / `ended` 처리 / 로드 실패 폴백 / 일시정지·재개·탭 숨김 / 덕킹 / 소리 끄기·켜기 / 클릭음 두 번째 입력부터 / `file://`와 서버 둘 다 / 터치 흉내). 교육용은 문제 팝업 덕킹·`ended` 안전성 추가. 이 항목들은 청각이 아니라 **호출 로그와 네트워크**로 확인한다.
5. **경계 시나리오**(직접 시도): 첫 입력이 일시정지 버튼·소리 토글인 경우, 소리를 끈 채로 시작해 판 중간에 켜기, 판 중간 새로고침, 탭 숨김 중 곡이 끝남, 빠른 연타로 레벨 카드 두 번, 결과 화면에서 곧바로 [레벨 선택], 네트워크 느림(`Slow 3G` 흉내 가능하면) 시 곡 사이 무음 길이.
6. **회귀**: 일반용·교육용 한 판을 끝까지(클리어와 실패 각 1회) 플레이해 콘솔 에러 0, 점수·별·저장·랭킹 제출 동작 이상 없음(랭킹 서버는 건드리지 않고 모의/오프라인), 교육용의 ? 문제 흐름 이상 없음.
7. **수정**: 명백한 결함(규칙 위반·시험 실패·누수·경쟁 상태)은 **최소 수정**한다(수정 가능: 일반용·교육용 `game.js`·`test/**`·`review.md`(이어 붙이기만)). 두 앱을 같은 방식으로 맞춘다(수정은 일반용 → 교육용 순). 수정하면 시험을 다시 돌려 개수를 기록한다. 설계 변경은 제안으로만.
