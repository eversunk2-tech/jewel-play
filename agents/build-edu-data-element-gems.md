## 일하는 법 (소단원마다 반복, 한 번에 1~2개씩)
1. 추출 텍스트를 읽고 **`facts` 목록**을 만든다(id `F01…`, 재서술 30자 이내 `s`). 이미지에 의존하는 내용·통계 숫자·민감 사건 직접 설명(§21.5.3)·4-2 2(2)의 특정 지역 자랑거리 예시는 **사실에서 제외**한다. 학습지에 없는 내용은 쓰지 않는다(**상식 보충 금지**).
2. §21.4.2의 **소단원별 변형 계획표 구간**(여유/보통/빡빡/매우 빡빡)에 맞춰 **60문제**를 쓴다: OX 24(O 12·X 12) + 객관식 36(보기 4개, 정답 위치 ①~④ 각 9개 ±2). 기법 코드 `k`를 고르게 쓰고(한 기법 25% 이하), **같은 사실에는 서로 다른 기법만**, 한 사실당 최대 4문제(빡빡 구간 5). 사용자는 **원본이 짧아 비슷한 문제가 반복되는 것을 허용**했다 — 같은 사실이라도 질문 형태·보기·관점을 바꿔 서로 다른 문제로 만들면 된다. 문제를 억지로 늘리려고 사실을 왜곡하거나 뜬금없는 보기를 넣지 않는다.
3. **정확성**: 모든 문제에 근거 `f` 필수. 정답은 학습지 사실로 **하나로 확정**되어야 하고, 오답 보기에 정답으로 읽힐 말이 없어야 한다(§21.4.3 오답 보기 규칙). OX를 거짓으로 뒤집을 때는 같은 소단원의 **비슷한 종류의 낱말**로만 바꾼다. 고유명사·인물·연도·음력 날짜는 학습지 표기 그대로. 해설은 §21.4.3 톤(`~해요/~이에요`, 까닭 1문장 + 헷갈리기 쉬운 것과의 차이 1문장, 야단·평가 표현 금지, 폭력·공포 묘사 금지).
4. **쉬운 말**: 초등학생이 읽는 문장(학년별 길이 상한 §21.4.3). 교과 용어는 그대로 쓰되 설명 문장은 쉬운 말로. 한 문장 한 생각.
5. **그림·표·그래프에 의존하는 표현 금지**("위 그림을 보고", "다음 표에서" 등), 외부 링크·`http` 금지, 보기에 "모두 맞다/없다/위 보기 모두" 금지.
6. 파일 형식은 §21.4.3의 **소단원 파일 예**와 정확히 같게(`(function (w) { var D = w.EDU_Q = w.EDU_Q || {}; D['soc-…'] = { v: 1, facts: […], items: […] }; })(window);`, 한 문제 한 줄, UTF-8, 작은따옴표 안 작은따옴표는 이스케이프).
7. **검증기를 돌린다**: `node apps/element-gems-edu/tools/validate-edu-data.js --file apps/element-gems-edu/edu-data/q/{소단원ID}.js --source-dir /private/tmp/claude-501/-Users-sungchul-Desktop-play2-jewel-play/a531f417-6e12-4899-8faf-38c202023dbb/scratchpad/edu/txt2`. **오류 0**이 될 때까지 고친다. **경고는 하나씩 읽고 정말 문제인지 판단**해 고치거나 이유를 보고에 적는다(민감어 경고 문항은 기본 제외·재작성). 정답 인덱스·보기 배열 위치를 마지막에 한 번 더 눈으로 확인한다(`a`가 맞는 보기를 가리키는지).
8. **스스로 사실 대조**: 완성한 소단원마다 무작위 10문항을 추출 텍스트와 다시 대조해 정답·해설이 사실과 일치하는지 확인하고 보고에 `대조 N문항, 불일치 M`으로 적는다(별도 Review 에이전트가 소단원당 15문항을 다시 대조한다).

## 부록 — 검증기 사용 메모와 규칙 보강 (E8 완료 후, 메인 세션 추가)
- 검증기: `node apps/element-gems-edu/tools/validate-edu-data.js --file <내 소단원 파일> --source-dir <원문 txt 폴더>` (여러 `--file`, `--unit soc-4-2` 같은 앞부분 선택, `--json`, `--quiet` 가능). 문항마다 `[오류][규칙] N번 필드: 문제점` + `-> 고치는 방법`이 나온다. 오류 0이 되어야 하고 경고는 하나씩 읽고 판단한다. 파일 머리 주석에 상세 설명이 있다.
- **강조 표기**: `q`(문제)에서 '옳지 **않은** 것', '**가장 먼저**', '볼 **수 없는**'처럼 **굵게 강조할 말만 `**…**`** 로 감싼다(문제 하나에 한 군데). 보기·해설에는 `**`를 쓰지 않는다. 글자 수에서는 `**`가 빠진다.
- **기법·정답 일치**: `tf-t`는 정답이 O(`a:1`), `tf-f`는 정답이 X(`a:0`)여야 한다(어긋나면 오류). 문제는 **한 문장**이어야 한다(두 문장 이상이면 오류). 이중부정 금지.
- 보기에 `모두`·`없음`·`전부`가 들어가면 오류다: 정상 문장이라도 걸리면 다른 낱말로 바꾼다.
- 한 사실당 문항 상한은 **5**(빡빡 소단원 `soc-4-2-1-1`·`soc-4-2-1-2`·`soc-4-2-2-2`·`soc-6-2-2-2`·`soc-6-2-2-3`은 6)이다(검증 표 기준). `facts`의 요약 `s`는 30자 이내, 모든 `facts` id가 최소 1번 쓰여야 한다.
- 카탈로그 쪽수 표기는 `'6-33'`. 카탈로그(`edu-data/catalog.js`)는 읽기 전용이다.
- **오탐·누락처럼 보이는 검증기 동작**은 고치지 말고 보고에 적는다(메인 세션이 조정한다).
