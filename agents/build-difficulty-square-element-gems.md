## 승인된 결정 (spec 본문의 열린 질문에 대한 답)
**§15**
1. 보석 종류는 **3난이도 모두 6종 유지**.
2. **경과 90초 이후 시간 보너스 ×0.5를 채택**한다. (경과 시간 기준은 게임 시작 후 플레이 시간. 시간 정지·컷인 중 정지된 시간은 경과에 포함하지 않도록 구현하고, 어떻게 정의했는지 보고에 적는다.)
3. 고수 게이지 최대치는 spec 표 값(약 -33%) 그대로.
4. 점수 배율 ×0.8/×1.0/×1.3 및 기존 `best`를 `normal`의 최고 점수로 이관하는 방식 그대로.
5. 초보 자동 힌트: 6초 무입력 시 4초 표시(spec 표 값).
**§16**
1. 2×2 보상은 기존 4매치와 동일(새 보너스 없음).
2. 정사각형 전용 연출은 **1차에서 제외**(범위 밖).
3. 시작 화면 규칙 문구에 "또는 2×2 정사각형" 안내를 **포함**한다.

## 구현 순서 (spec §15.6, §16.4의 단계 분해를 따른다. 단계마다 확인 후 다음으로)
1. **2×2 규칙(순수 로직)**: `findMatches`(2×2 검출 + 3연속과 합집합 그룹화), 초기 보드 생성·재섞기의 2×2 회피, `hasValidMove`/`listMoves`/힌트 탐색에 2×2 반영. 순수 함수는 DOM과 분리 유지.
2. **난이도 프리셋**: `CONFIG`를 `CONFIG.difficulty[level]` 구조로 정리(게이지 최대치·시간·시간 보너스·힌트·스킬 효과 수치·점수 배율). 게임 시작 시 선택된 난이도 값이 적용되도록 하고, 하드코딩된 값이 남지 않게 점검.
3. **UI/저장**: 시작 화면 난이도 선택(초보/중수/고수 3버튼, 기본 중수, 선택 유지), 난이도별 간단 설명, 게임 중·종료 화면에 난이도 표시, 난이도별 최고 점수 표시, `element-gems:v1` 저장 구조 변경과 마이그레이션(기존 `best` → `bestByLevel.normal`). 저장 접근은 모두 `try/catch`.
4. **초보 전용 동작**: 자동 힌트(6초 무입력), 힌트 쿨다운 등 프리셋 반영. 시간 보너스 감쇠(경과 90초 이후 ×0.5)는 3난이도 공통.
5. **기존 기능과의 상호작용 점검**: 컷인/스킬/일시정지/리셋/재시작에서 난이도 값이 올바르게 적용·초기화되는지, 스킬 후 연쇄에서 2×2가 동작하는지, 칭찬 팝업 "4매치" 조건에 2×2 포함.

## 자체 점검 (완료 전 필수)
- Node 순수 로직 테스트: 2×2 단독 / 3×3 블록(그룹 크기 9) / 2×2+3연속 겹침 / 가장자리·모서리 / 초기 보드·재섞기 각 500회에서 매치 0·2×2 0·유효한 수 ≥ 1 / `listMoves`·힌트가 2×2 수를 포함.
- 가능하면 난이도별 시뮬레이션(캐주얼, 소수 판)으로 스킬 횟수·판 길이가 spec §15.3 표와 크게 어긋나지 않는지 확인.
- 브라우저(로컬 http 서버): 난이도 3종 각각 시작 → 시간·게이지 최대치 표시가 표와 일치, 난이도 변경 후 재시작 시 상태 초기화, 저장 마이그레이션(수동으로 옛 형식 데이터를 넣어 시험), 콘솔 에러 0건, 360×640 / 390×844 / 가로 800×360에서 난이도 선택 UI가 깨지지 않음.
- 알려진 상태: 이전 Review 통과 항목(컷인 1회 실행, 타이머 정지 등)이 깨지지 않았는지 스킬 6종 한 번씩 재확인.
