# Plan 지침 — 목표 유형 계단·톱니 곡선·비폭력 특별 레벨·선물상자 대폭 증가 (새 spec §)

## 역할
너는 **Plan 담당**(Sonnet 서브에이전트)이다. 구현하지 않는다. `apps/element-gems/spec.md` 끝에 **새 §**(마지막 § 다음 번호; 지금 §25가 마지막이고 **§26(보드 구조)** 을 다른 Plan 에이전트가 쓰는 중이니 너는 **§27**)를 **추가**한다. 기존 §는 **한 줄도 고치지 않는다**(삭제 0줄 확인). 이 일은 **분석 + 정밀 설계 + 시뮬레이션 보정 + 조사**다. 계획서는 사용자 승인 전이다.

## 사용자 요구 (2026-11-08, 대화 요지)
1. "시간 안에 목표 점수 도달이 10단계로 갈수록 어려운데, 10단계가 너무 쉬워도 게임성이 떨어지고 너무 불가능해도 의욕 상실이다. **고수는 시간당 목표 점수 채우기 말고 다른 방식**도 고려하자. **전면 수정도 가능**하다." (우리가 3번 오르내린 목표 점수 9300→3800→6100 자체가 점수 목표의 한계를 보여 준다.)

3. **"보스와의 전투가 폭력적인 느낌이면 학습용으로 곤란하다. 이 부분의 해결점을 다른 게임이나 자료를 분석해서 제안해 달라."** → 전체 이용가·초등학생 대상 안전 규칙(CLAUDE.md: 폭력·선정·공포·도박 없음)에 맞는 **비폭력 특별 레벨(보스류) 프레임**을 조사해 제안한다.

5. 기존 사용자 원칙: **"고민하며 도전하는 곳은 고수에서만", 고수도 시간 안에 풀 수 없는 점수의 벽이 아니어야, 10단계 도달은 너무 쉽지도 불가능하지도 않게**. 서버 변경이 없는 안을 중심으로(별은 계속 **남은 시간** 기준).

## 설계할 것 (정밀하게)
1. **미션(목표) 카탈로그와 정의**: 수집(원소별 개수), 연쇄, 큰 매치(4개 이상·2×2), 스킬 사용 횟수, 스킬로 지운 개수, 시간 보너스 획득, (교육용) 선물상자 문제 맞히기, 복합(둘 이상) 등. 각 미션에 **정확한 카운트 규칙**(직접 매치만? 스킬로 지운 것은? 연쇄 단계는?), 시뮬레이터로 측정 가능한 정의, 난이도 지렛대(개수·조합·제한), **속도·스킬 습관 민감도와 변동성을 측정**해 표로(sim-m.js 확장). 일반용·교육용 공통/교육용 전용 구분.
2. **난이도별 목표 유형 계단과 톱니 곡선**: 3난이도×10레벨 **30개 레벨 표**(레벨마다 목표 유형·수치·특별 레벨 여부), 초보 앞쪽에서 스킬을 쓰게 되는 설계, 중수에서 스킬·연쇄를 배우는 설계, 고수에서 복합·전략(고민)이 필요한 설계. **톱니**(3·6·9단계 한 템포 쉽게, 5·10단계 특별 레벨 — 값은 근거와 함께 조정 가능). **기준 플레이어와 클리어율 곡선**을 난이도별로 정의(예: 10단계 25~35%, 같은 레벨 초보<중수<고수)하고 **새 시드·셀당 ≥600판 시뮬레이션으로 보정**해 표로 제시(플레이어: 수당 2.0·2.5·3.0·3.5·4.0초 × 스킬 씀/가끔/안 씀 × 수 고르기). 숙련자가 10단계를 100% 깨지 않게. 서버 변경 없이 **별은 남은 시간 기준 유지**임을 코드로 확인해 적는다(`LEFT_CAP` 등 상한과 충돌하지 않는지).
3. **화면·문구**: 미션 진행 표시(목표 바를 미션 칩 등으로), 레벨 선택 화면의 미션 설명, 결과 화면, 초등학생이 읽을 쉬운 말, 접근성(색에만 의존 금지, 터치 ≥44px, 대비). 세션 scratchpad에서 현재 CSS 사본으로 **실제 렌더링한 시안 스크린샷**(로컬 정적 서버·`apiBase` 비움, 새 탭 + 로컬만)을 만들어 경로를 적는다. 프로젝트 폴더에는 남기지 않는다.
4. **비폭력 특별 레벨(보스류) 프레임 — 조사 필요**: 전체 이용가·초등 대상 게임·교육 게임·등급 기준(한국 게임물관리위원회 전체이용가, ESRB Everyone, PEGI 3 등의 폭력 표현 기준)을 `WebSearch`로 조사하고, 어린이 대상 매치-3·퍼즐·교육 게임이 "적과의 싸움" 대신 쓰는 프레임(예: 정령 구조·정화·깨우기·얼어붙은 것 녹이기·식물 키우기·탐험·복원, 길들이기·친구 되기 등)을 사례와 함께 정리한다. **3개 이상의 비폭력 프레임 안**을 만들어 각각의 장점·위험·컨셉(원소)과의 일치·**새 에셋 필요 여부**(없는 안을 우선; 필요하면 CLAUDE.md의 에셋·Gemini 규칙, 유명 작품 연상 금지)·교육 연계 가능성·규칙(체력바를 "회복 게이지"로 바꾸는 식의 구조)을 비교하고 **권장안**을 정한다. 폭력적인 어휘·연출을 피하는 **문구 가이드**도 만든다. 찾지 못한 것은 찾지 못했다고 쓴다.
5. **선물상자 대폭 증가 설계**: 목표 **한 레벨 평균 문제 수**(근거와 함께, 예: 6개 이상)와 그에 맞는 **스폰 규칙**(칸당 확률·판 위 최대 수·**연속 질문 간격 보장**(최소 N수 간격 또는 최소 시간)·첫 행동 확정), 시뮬레이션으로 측정(교육용 엔진 `edu-rv1/sim-real.js`/`run-q.js` 참고). **흐름 영향**(질문 간격, 질문 하나당 소요 시간은 가정으로 명시), **수업 시간 모델**(40분 수업에서 몇 레벨/몇 문제), 조커가 많아지면 매치가 쉬워지는 효과와 교육용 목표 배율(×1.2) 재산정. **문제가 늘어도 점수 격차가 아니라 학습으로 이어지게**: 정답 보너스의 재설계(예: 문제 수에 반비례, 목표 대비 비중 상한), 점수 외 **학습 보상**(별도 진행도·배지·단원 마스터 표시 등, 게임 진행과 분리), **학습 미션**(선물상자 문제 N개 맞히기를 교육용 미션으로)과의 연계, **학습 강도 선택**("보통/많이", 교사·학생, 기본값과 저장). 틀린 문제 재출제·복습은 사용자가 나중으로 미뤘으니 **이번 범위 밖 후보로 한 줄**만. 학생 반응·질문당 시간은 확인할 수 없으니 가정과 한계를 적는다.
6. **구조·단계·검증**: 일반용·교육용 동시 반영(`tools/SYNC.md`, `[EDU]` 표식), **변경 영향 범위·파일 소유권·단계 분해(Build용)** — 큰 작업이므로 **단계**(예: ① 미션 엔진·HUD ② 레벨 표·난이도 보정 ③ 교육용 ?·학습 보상 ④ 비폭력 특별 레벨)로 나누고 각 단계가 독립적으로 시험·배포 가능한지, **기존 시험(일반용 123·교육용 301·서버 65) 유지**, 새 시험 계획. **검증 체크리스트(Review용)**, **열린 질문(최대 5, 권장안 먼저)**, **위험·한계**(비폭력 판단의 주관성, 속도 민감도, 사람 체감 미확인, 기존 저장 진행도·별과의 호환), 서버·순위 영향(별 계산·`STAGES`·저장 구조 변경 여부; **없어야 한다**). 저장된 진행도(`stages` 배열의 `stars`·`left`)와 호환되는지 적는다.
7. **다른 계획과의 관계**: §25.6 목표 표는 점수 유형 레벨에서 재사용 또는 대체되는지, §26(보드 생성·리필 구조)과의 의존(미션 보정은 보드 생성이 바뀌면 다시 해야 함)을 표로.
